我的结论是：问题5应该用 Godot 4.6 + C# 实现，放在现有游戏项目中，做成一个独立的开发工具场景。

不推荐继续用 WPF，也不建议一期就做 Godot `EditorPlugin`。

### 为什么选 Godot

`lucky-item-loot-editor` 适合 WPF，是因为它的核心是表格、数字和 JSON 编辑；DogSkin 工具的核心却是“预览必须和游戏最终效果一致”。

当前小狗表现包含：

- `DogSkin` 的头、耳朵、眼睛、舌头、爪子、固定眼镜。
- `DogReaction` 的继承和 Override。
- `layer_index_v1/v2.json` 坐标。
- 眼镜、帽子的 PSD 中心点偏移。
- 爪子层级、翻转、表情和动画。
- Godot 实际的纹理导入与渲染结果。

这些逻辑目前集中在 [DogVisual.cs](G:/Workspace/godot-project/lucky-dog-pub-2026/lucky-dog-rise/Scripts/DogVisual.cs:568) 和 [DogArea.tscn](G:/Workspace/godot-project/lucky-dog-pub-2026/lucky-dog-rise/Scenes/DogArea.tscn)。

如果用 WPF，就必须重新实现一套坐标、图层、翻转和表情组合逻辑。短期能显示图片，后续一定会和游戏实际效果产生偏差。Godot 则可以直接实例化与游戏相同的预览节点。

### 推荐形态

建议在现有 `lucky-dog-rise` 项目里增加一个独立场景，例如：

```text
Tools/DogSkinEditor/
├── DogSkinEditor.tscn
├── DogSkinEditorController.cs
├── DogSkinDraft.cs
├── DogSkinAssetCatalog.cs
└── output/
```

通过 F6 或专用启动脚本运行，不启动 `ModeManager`、Steam、存档和完整游戏。

一期不做 `EditorPlugin`，原因是：

- 独立场景开发和调试更简单。
- 不依赖 Godot 编辑器插件生命周期。
- 将来体验稳定后，仍可包装成编辑器 Dock。
- `Tools/**` 可以从正式导出中排除。

### 一期界面

可以采用三栏结构：

- 左侧：素材库  
  选择狗狗文件夹、头型、耳朵、眼睛、舌头、爪子、固定眼镜。

- 中间：1200×1200 原始比例预览  
  使用真实 `DogArea` 节点和定位算法，可切换表情、帽子及背景明暗。

- 右侧：DogSkin 草稿  
  编辑 ID、各字段，显示缺失素材、缺失坐标、无效引用等问题。

现有 12 个 DogSkin 本质上是四种素材目录与三种头型的组合，因此还应支持：

- 导入已有 DogSkin。
- 克隆为新草稿。
- 快速轮换所有 `DogReaction`。
- 一键遍历帽子，检查兼容性。
- “无眼镜”与固定眼镜切换。
- 放大检查眼睛、眼镜和嘴筒区域。

### 数据边界

一期不应该直接修改 Excel，也不要直接修改 Luban 生成的 `Data/Json/tbdogskin.json`。

建议流程是：

```text
PSD 导出素材
    ↓
DogSkin 可视化工具读取素材、layer_index 和现有 JSON
    ↓
保存 DogSkinDraft.json
    ↓
复制为 TSV/CSV 行
    ↓
人工填写 Excel
    ↓
Luban 正式生成
```

以 JSON 作为草稿主格式，因为更安全、可恢复，也方便继续编辑；另外提供“复制为 TSV 行”，可以直接粘贴进 Excel。

### 需要复用而不是复制的代码

不建议在工具中重写一份 `DogVisual`。应抽出一个很小的共享表现层：

```text
DogSkin 表 → DogAppearanceSpec
工具草稿  → DogAppearanceSpec
                      ↓
              同一个 DogVisual 渲染器
```

这样工具预览和游戏运行时始终使用相同的：

- 表情解析；
- 资源路径；
- PSD 坐标；
- 眼镜与帽子位置；
- 图层顺序。

### 一期暂不包含

为了不把前面几个问题混进来，一期先不做：

- 狗狗背包图标自动合成；
- 直接写 Excel；
- 眼镜和帽子的层级配置编辑；
- 完整盲盒或背包装备流程；
- 批量 PSD 导出。

这些以后可以作为独立模块接入。

所以最终技术选择是：

> 同一 Godot 项目内的独立 C# 开发工具场景，以真实 `DogArea/DogVisual` 为预览核心，JSON 草稿为输出；不采用 WPF，不在一期做 EditorPlugin。
