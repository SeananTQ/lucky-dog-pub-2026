- [ ] 增加 Steam Inventory 异常同步后的“找回物品”兜底流程
  - 目标：解决网络波动、异步交易、多设备登录、盲盒表演中途退出等情况下，客户端无法可靠判断 Steam 库存新增物品来源的问题。
  - 不再强求在异常情况下恢复“某件物品究竟来自哪一次盲盒/交易”的完整历史归因，只保证玩家不会错过已经合法进入 Steam Inventory 的新物品。
  - 当客户端发现 Steam Inventory 中存在“本地尚未确认展示过”的新增物品，且无法可靠归因时，将这些物品统一记录为待找回物品。
  - 玩家下一次打开背包时，弹出“找回物品”对话框，集中展示这些新同步下来的物品图标。
  - 文案可类似：
    - “小狗帮你找回了一些还没来得及告诉你的物品！”
    - “这可能是由于网络波动、异步交易或在其他设备上登录游戏造成的。”
    - "这些物品可能因为网络波动、异步交易或在其他设备上登录，之前没来得及展示给你"
    - “谢谢小狗，小狗真棒！”
  - 玩家确认后，将对应物品标记为已经展示/确认，避免重复弹出。
  - 如果玩家在普通盲盒的揭晓表演过程中退出游戏、崩溃或发生异常中断，下次启动时不恢复旧的盲盒动画状态；对应尚未完成展示的奖励直接进入上述“找回物品”流程。
  - 后续实现时可考虑以 Steam Item Instance ID 为基础维护“已确认展示物品”状态，而不是依赖完整的奖励来源归因。
  - 普通盲盒物品本身不允许上架 Steam 市场；未来可交易物品主要来自熔炼或活动奖励，并与普通盲盒物品使用不同的道具集合/类型，从设计层面进一步降低库存同步时的归因歧义。
  - 此方案定位为 Steam Inventory 的最终异常兜底层，而不是正常奖励流程；正常情况下仍按现有“提前准备待揭晓奖励 → 倒计时结束后播放盲盒表演并展示奖励”的流程运行。
