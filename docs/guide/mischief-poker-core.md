# 捣乱德州第一阶段：规则核心与逻辑验收

玩法规则见[捣乱德州玩法设计](../game-design/捣乱德州玩法设计.md)。本文记录第一阶段的程序边界、调用约定和逻辑验收，不替代策划规则。后续主场景本机试玩见[第二阶段说明](mischief-poker-preview.md)；真实联机牌局尚未接入。

## 本阶段范围

核心位于 `lucky-dog-rise/Scripts/Rooms/Poker/`，不依赖 Godot 节点、Steam、房间显示层、单机 `GameData`、存档或库存。内部名称 `MischiefPoker` 用于区分玩法，不代表英文展示名称已经确定。

- `PokerHandEvaluator`：验证 0～51 的卡牌编码，比较五张牌及七张中的最佳五张，保留结算展示所需的五张实体牌。同牌型比较完整有效点数，不用花色或未入选五张的牌打破平局。沿用 `EHandRank`，其中 `Nothing` 在多人比较中表示高牌，不表示失去比牌资格。
- `MischiefPokerMatch`：固定座次的权威牌局，支持 2～6 名参与者；发牌、翻面、结束操作、超时、统一补牌、分奖和下一局庄家轮转均在这里处理。
- `MischiefPokerModels`：规则参数、命令、公开视图、本人暗牌视图和结算结果。快照及其中的集合不会随后续操作发生变化，也不能借集合修改核心状态。

单机 `CardEvaluator` 及其中奖倍率逻辑不作改动。核心源码在 `DEMO_BUILD` 和 `RECORDING_BUILD` 下排除；测试项目位于游戏目录外，不进入游戏导出。

## 生命周期与调用

创建 `MischiefPokerMatch` 时传入固定座位顺序及首庄成员 ID。正常首局的首庄由房主担任；第一阶段要求首庄包含在参与名单中。成员 ID 使用房间会话内的身份键，可以包含陪伴小狗的负数 ID，不以显示位置或 SteamID64 的截断值作为身份。

1. `StartHand(nowSeconds)` 校验余额，收取每人 100 底注，发两张暗牌并亮出五张公共牌。初始余额默认为 1000，同一对象连续下一局沿用结算余额。
2. 权威端持续调用 `AdvanceTo(nowSeconds)`，使用单调递增的真实秒数。读取视图本身不推进计时。
3. `Act(command, nowSeconds)` 接受当前行动者的翻面或结束操作。一次回合最多两次翻面；第一次翻面不重置 15 秒期限。
4. 所有人结束后进入 `AwaitingDraw`。此时仍保留最后一次翻面的公共牌状态，方便后续界面播放反馈，任何玩家都不能再操作。
5. 权威端调用 `ResolveHand()`，统一替换待换牌并结算，产生换牌记录、获胜牌型、分奖及下一局庄家。重复结算会被拒绝。
6. 结算后保持 `Settled`，直到后续业务明确请求下一局；不自动决定准备、连续开局或房间成员参与规则。

正常洗牌使用不重复的 52 张牌和随机洗牌。`StartHand` 的可选完整有序牌堆只用于权威端可重复测试；不能把这个入口开放给客户端。测试发牌按固定座次发两圈，再发公共牌。弃掉的旧公共牌在本局不回牌堆。

精确到达期限时先执行超时，再判断玩家操作。长时间未更新后按原期限依次结束已超时回合，不给每个过期回合重新赠送 15 秒。所有回合结束后仍等待权威端统一补牌，不擅自开始下一局。

## 筹码与未定规则的边界

本阶段只维护内存中的临时筹码，不读写或合并单机筹码。正式经济互通仍以策划讨论为准。

- 初始 1000、底注 100、回合 15 秒、最多连庄 4 局通过 `MischiefPokerRules` 配置；每回合两次翻面的规则保持固定。
- 平分余数作为系统收走的荷官小费：结算记录 `SystemTip`，会话累计 `TotalSystemTips`。校验恒等式为“所有玩家余额 + 未结奖池 + 累计小费 = 初始总筹码”。
- 余额不足时，核心拒绝整局开始，返回 `InsufficientChips`；不部分扣费、不让余额变负、不自动补发，也不自动淘汰成员。产品层的补充筹码或退出流程尚未确定。
- 每次翻牌追加 50 筹码仍是未采纳的候选规则，当前翻面不产生额外费用。
- 第一阶段参与名单固定，不实现中途入座、离桌、换人、掉线接续或重新入房补发。2～6 人是核心能力范围，不代表产品最低开局人数已经敲定。

## 命令与暗牌边界

命令携带本次会话 ID、牌局编号、预期修订号和成员身份。已执行命令的重复发送、上一局迟到操作及过期界面发出的命令都不能再次改变牌局。收到版本过期结果后应刷新视图，不自动重放翻牌，否则可能撤销玩家上一条已经成功的操作。

核心只能由一个权威执行端单线程驱动。成员身份与时钟必须由未来的房间适配器校验和提供，不能信任消息正文自报的成员 ID 或客户端时间；当前命令校验不等于已经完成 Steam 身份认证。

`GetPublicView()` 不包含暗牌或剩余牌堆；`GetPlayerView(playerId)` 只补充该成员自己的两张牌。两者都不会暴露将要补入的新牌。已经展示过、后来翻成背面的公共牌仍然是公开信息，不能误当作需要重新保密的新牌。

结算后才公开参局者手牌、最佳五张和奖池分配。未来发送本人视图前，必须验证接收方身份。不能把包含所有暗牌的对象先广播，再依靠界面隐藏。

## 开发测试入口

使用 .NET 8 控制台测试，链接同一份生产核心源码，不需要启动 Godot、Steam 或游戏窗口：

```powershell
$env:NUGET_PACKAGES = "C:\Users\carlo\.nuget\packages"
dotnet run --project tests/MischiefPoker/MischiefPoker.csproj -c Release
```

若本机无法访问 NuGet 审计服务，本测试项目没有第三方包，可临时离线恢复后运行；这不修改游戏项目的依赖或审计配置：

```powershell
dotnet restore tests/MischiefPoker/MischiefPoker.csproj --ignore-failed-sources -p:NuGetAudit=false
dotnet run --project tests/MischiefPoker/MischiefPoker.csproj -c Release --no-restore
```

用例覆盖：

- 全部 2,598,960 种五张牌组合的牌型频数与 7,462 种不同牌力，以及 A 的大小顺子、同牌型比较、最佳五张和花色平局。
- 0／1／2 次翻面、同槽两次、后手撤销前手、全部保留／全部换牌、暗牌不变、无重复牌、超时及恰好截止时的操作。
- 首庄、不同座次、正反方向、四连庄触顶、第四局被其他玩家赢走、平局强制下庄，以及强制下庄后的原庄家首位行动。
- 暗牌投影、只读快照、错误身份、重复／过期操作、无效牌堆、重复结算、余额不足、奖池平分和系统小费账目。
- 固定种子的 2～6 人连续模拟牌局；每一步检查资金总额，结算时检查牌堆唯一性和回合次数。

这些测试证明规则层行为，不替代 UI 视觉、真实联机、断线恢复或机器人策略验收。第二阶段接入 UI 时提供自动操作的模拟玩家与调试控制，后续再完善正式陪玩策略。本阶段没有新增游戏内可见入口。
