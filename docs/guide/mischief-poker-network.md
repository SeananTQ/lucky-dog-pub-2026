# 捣乱德州：房间参局与网络同步

玩法见[捣乱德州玩法设计](../game-design/捣乱德州玩法设计.md)，表现规则见[牌手面板设计](../game-design/牌手面板设计.md)。本阶段把已有规则核心和局间演出接入房间，保留[本机试玩](mischief-poker-preview.md)用于调节显示。

## 当前玩家流程

- **统一房间玩法**：捣乱德州与一起聊天、各自工作并列，接入当前玩法下拉菜单和既有投票；新房间默认一起聊天。玩法、准备状态和个人桌宠／扑克视角分别管理。
- **同一份成员名单**：原房间成员列表显示参局状态与请出操作，不另建扑克名单。首次投票切入时，明确同意的真人自动准备；陪伴约一秒后自动准备。开场前其他真人可在本人行准备或取消准备；开场时未准备者和中途加入者均为旁观者，之后使用入座／取消入座。入房身份变化不继承原身份的同意记录。
- **房主开始**：房主没有独立准备按钮，点击开始即确认本人参局；至少两名参局者，真人与陪伴都计数。未准备者不扣底注、不收暗牌。准备区不再显示独立取消牌局按钮，本机试玩入口保留。
- **统一扑克界面**：房间切入捣乱德州后，所有成员（包括未准备、旁观和离座者）的扑克视角都显示联机信息面板，不再允许单人下注。系统面板与左侧信息面板共用操作权限和业务状态，但显示范围不同：系统面板保留房主的开始／继续／重开、开场前成员的准备／取消准备、开场后的入座／取消入座及实际暂停后的离座；打完暂停／取消暂停、打完离座／取消离座只在扑克左侧信息面板显示。系统面板成员行显示参局、待离座、旁观、待入座或已入座，没有牌局操作时收起整行按钮。没有正式余额时显示占位符，不冒用个人筹码。不在按钮上方增加说明段落，使用按钮文字、颜色、可用状态及悬停提示表达。
- **单人局舍弃**：进入捣乱德州房间时舍弃未完成单人牌局及尚未领取的奖励，不退还已付单人底注，不影响已入账个人筹码。旧发牌／补牌延迟回调不能重新启用单人操作或生成奖励。离房或切回非扑克玩法后恢复单人扑克；盲盒奖励不属于可舍弃内容。
- **开盒并行**：联机扑克中保留盲盒入口，费用仍使用个人筹码。开盒只占用本机交互，不撤销准备，不停止权威时钟、超时、结算或下一局。关闭后显示最新状态，不补播已错过的整局。
- **提前显示牌手面板**：正式切入玩法后即显示无牌等待面板；没有正式座位和余额时显示占位符。桌宠本人也显示牌手面板，持牌后可查看自己的暗牌与行动进度；其他人的暗牌仍为牌背。开始牌局、后来加入或收到快照均不强制进入扑克，玩家手动切换视角。
- **继续与重开**：房主“打完暂停／取消暂停”预约或撤销派彩后的停留。预约不在成员 UI 显示；真正暂停后，信息面板结果标题显示“已暂停”。房主同时看到“继续／重开”：继续保留老成员座位、余额、下局庄家、连庄和方向，也接纳已申请入座的旁观者；重开创建新牌桌，重新分配本次参局者座位、初始 1000 筹码，由房主首次坐庄。两条路径均先收旧牌，再扣新局底注；暂停后不因有人申请入座而自行恢复。
- **旁观与入座**：至少两名参局者即可开始，不要求全体房间成员准备。开场时未准备者、中途加入者和已离座者都可能旁观，没有单独旁观按钮，不扣当局底注、不发当局暗牌。旁观者“入座／取消入座”表达下一局参局意愿，自动续局和房主继续均可接纳。首次入座在下一局成功发牌时追加座位并分配 1000，再扣 100；老成员回到原位，只扣一次底注，不补发余额。
- **离座与返回**：成员“打完离座／取消离座”不撤销当局手牌、行动或结算资格。下一局不扣离座者底注，不发牌，保留原座位和余额。真正暂停后已入座成员使用“离座”，可立即改变后续参局意愿；回座后按钮恢复“离座”。收牌期间锁定离座和入座，迟到的旧局命令无效。应接庄者离座时，按既定方向从其后寻找首个入座者，连庄重置为 1。
- **筹码边界**：临时初始 1000，每局底注 100，与个人筹码和盲盒资产分开。拟继续参局者不足 100，或入座人数少于两人时停留在结果，不能通过“继续”绕过；房主可以“重开”重置本次参局筹码。正式不足处理已记入 `my-todo.md`，不把临时补满规则当作正式经济规则。

完整产品规则见[房间玩法与开局准备](../game-design/捣乱德州玩法设计.md#房间玩法与开局准备)、[房主暂停续局](../game-design/捣乱德州玩法设计.md#房主暂停续局)及[牌手面板的桌宠视角](../game-design/牌手面板设计.md#房间玩法与桌宠视角)。新文案提供中文及临时英文回退，正式英文名称和完整多语言仍待统一。

`UiInteractionOccupancy` 继续负责本机输入与自动提示避让，不能决定全桌是否推进。返回桌宠、开盒或整桌暂停均不等于退出参局；隐藏期间仍接收同步，不能重复报名、补发筹码或延长回合。

房主在牌局进行中仍可使用玩法下拉菜单。点击“切换”时，若牌桌尚未真正暂停，则显示现有形式的确认遮罩：“预约暂停”复用信息面板的暂停请求；“好的”（`Got it`）仅关闭提示，不预约或撤销暂停。已有暂停预约时提示已预约，并禁用重复预约；收牌期间暂时禁用预约，待新局开始后恢复。保留选中的目标玩法，但预约与暂停均不自动发起投票或切换。

全部派彩完成、`Continuation == Paused` 后，房主再次点击“切换”才进入现有 60 秒多数投票及房主确认流程；人数或筹码不足导致的自动暂停也适用。投票期间两个入口的开始／继续／重开均不可用，`PokerNetworkSession` 同时拒绝绕过按钮的对应命令。该限制读取 Lobby 的有效投票状态，Mock 与 Steam 使用相同语义，不增加扑克传输字段或改变协议版本。投票取消、超时或确认失败保留原牌桌、筹码、座位、庄家与准备状态；取消或超时解除限制，但不自动续局。

投票成功后才结束旧场并切换房间玩法，清理旧牌桌和准备状态，保留成员与个人资产。再次切入捣乱德州走新的准备流程，不恢复旧场余额。对话框在离房、换房、房主或牌桌变化、断联、切走页面及关闭系统面板时失效；实际暂停后收起预约提示，仍等待房主主动点击“切换”。参局者退出／被请出仍按下节的中止保护处理。

## 同步与权限边界

- `PokerNetworkSession` 是每个客户端的牌桌端点；只有房主创建和推进 `MischiefPokerMatch`。房主掌握洗牌、未发牌堆、各玩家暗牌、行动时钟和筹码结算。当前属于信任房主的休闲牌局，不具备独立服务器级反作弊能力。
- Steam 传输使用共享 Steam 会话和回调泵，在 `ISteamNetworkingMessages` 的独立通道 7 上发送可靠消息。加入会话和收到消息都检查当前房间真人成员；不另建 Steam Runtime，也不通过 Lobby 成员数据或聊天广播暗牌。实现依据见 [Steam 官方接口说明](https://partner.steamgames.com/doc/api/ISteamNetworkingMessages)。
- 传输身份、房间代码与玩法、双方本次入房标记、牌桌 ID、命令序号、局号和修订号共同限定消息归属。发送者实际身份覆盖命令自报的玩家编号；过期、重复、错误房间、错误入房标记、非行动者及越权控制均不改变牌局。
- SteamID 字符串用于识别成员，另分配固定牌桌编号；各客户端已有的小狗本地 ID 仅用于显示映射。不能假定每台电脑的“玩家 1”是同一个人。
- 房主给每位成员分别生成快照：当局参局者只收到自己的两张暗牌，等待和离座者不收到暗牌；结算后才包含当局参局者的摊牌结果。`Playing` 表示已有牌桌席位，`ActionOrder` 才是当局参与名单；离座者保留账本席位但不在该名单内。未发牌堆和未来补牌始终不发送。绿框、决胜牌强调和动画仍由各客户端按本人视角计算。
- 操作成功或拒绝后由权威状态确认。客户端有未确认操作时暂不接受第二次操作，不自动重发翻牌，避免一次点击被执行两次。消息有大小、字段、牌面与身份检查，并限制单成员命令频率。
- 发牌预留三秒，随后开始权威行动时钟；每个回合仍为十五秒。有效操作立即推动同步，牌局中另有每半秒的状态校正；空闲状态使用较低频率。
- 局间采用房主权威计时，不再等待客户端演出完成回应。结算阶段按补牌整理预留时间、亮牌及赢家数计算派彩时长，之后进入收牌阶段，最后才扣注并发新局。隐藏或迟到客户端按快照进度赶上；动画状态不写筹码账本。旧完成回应被忽略，不能提前开始下一局。
- 续局状态为自动、已预约暂停、已暂停、续局收牌中、重开收牌中；暂停／取消／继续／重开命令绑定牌桌与局号，仅接受房主请求。收牌后名单锁定，不接受旧局的准备变更、暂停或重复继续。续局先校验有效参局名单及余额，失败不能部分扣注或改变上一局结果；重开更换牌桌 ID，拒绝旧牌桌命令。
- `Ready` 在开场前表示已准备，开场后表示下一局愿意入座；不代表已经拿到本局手牌。`BeginHand` 从全体愿意入座者生成下局名单，将 `!Playing && Ready` 作为新座位传入规则核心；发牌成功后才标记 `Playing`。既有真人席位一直保留，不能通过离座、取消再入座获取第二份初始筹码。
- 当前网络协议版本为 5。公开视图携带本局已接受的翻牌记录（最多六人各两次），包含动作版本、行动人、回合内序号、槽位及朝向；不含额外暗牌、牌堆或未来补牌。版本 5 另携带 `RetiredCompanions`，只用于结算后保留已退场陪伴的当局身份与结果，不表示这些小狗仍在房间或下一局参局。旧协议消息不接收；真实联调需使用相同构建，未实现不同版本混用。
- JSON 消息中的 record 构造参数与属性名属于协议。相关类型已加入混淆保留名单；修改类型时需同时检查混淆后的消息往返。

## 翻牌爪子的本机表现

牌桌与本机试玩使用共用的 `PokerPawEffects` 和 `CardPushAnimation`。房间层把公开动作转换成源爪子、目标牌及触牌回调，共用动画不接收房间身份或 `PokerFlip`；单机与教学接入见[共用爪子推牌与卡牌动画](poker-push-animation.md)。公开动作记录避免同一帧收到两次同槽翻牌时丢掉左右爪顺序；新局、隐藏后恢复或首次收到中途快照不追播旧动作。客户端在成功提交本机操作后立即预测翻牌表现，收到相符权威记录时去重，被拒绝或连接失效时恢复权威牌面；预测不修改账本、行动资格或权威牌局。

远端爪子前推后才启动该卡牌的视觉翻转，权威计时照常运行。临时爪子副本在宿主窗口图层绘制，源爪子只临时隐藏，不更换其父节点或位置；返回路径实时读取目标位置。离房、重开、遮挡及模式切换释放副本并恢复源爪子。系统补牌不产生玩家翻牌动作。新增协议类型及 Godot 组件须同时保留混淆名称。

推牌方向取本机屏幕内源爪子到目标牌的方向，限制为偏离屏幕水平线最多 35° 的左右斜推，再换算到卡牌局部坐标；每个客户端摆位不同，方向可以不同，无需网络传输方向。正上／下方的水平分量接近零时，左爪向右、右爪向左。临时爪子从源精灵基向量旋转，保留右爪镜像；本机保留源爪子的尺寸，远端仍按卡牌宽度适配。卡牌使用独立材质作同方向的透视翻面，纹理在中点切换，保持点数可读；系统补牌与亮手牌仍沿用原表现。返航位移持续 0.38 秒，角度单独在前 0.10 秒内转正；回收或中断必须清除投影参数。

## 结算表情

`RoomPokerTableView.DogReactionFor` 只读取 `Round.DisplayView`，并以 `WinnersVisible` 为结算展示门槛；`ActionOrder` 决定本局参局者，不能只看保留原座位的 `Seats`。普通赢家／并列赢家使用 `Excited`，独赢且葫芦及以上使用 `Starstruck`，落败使用 `Bored`；结果展示之前及收牌期间使用 `Default`，未参局者返回空值。

正式牌局和本机试玩通过同一入口更新本机扑克狗、桌宠狗及两种视角的远端小狗。`DogVisual.SetRoomPokerReaction` 只覆盖显示，不改写 `CurrentReaction` 或向房间同步结果表情；普通活动更新仍保存为底层状态，避免每帧或重复快照重新应用表情。换肤重用同一个覆盖状态，清除时恢复最新底层状态与舌头活动。Demo／录屏不包含此覆盖入口。

## 陪伴让位与成员动画

房间服务在捣乱德州中不因真人入房立即缩减陪伴名单。只有房主的 `PokerNetworkSession` 通过 `PokerRoomContext.ReconcileCompanions` 请求退场：准备阶段、已中止且没有有效牌局时可以调整；进行中的牌局必须等到当局结算及权威派彩时间结束，包括房主预约暂停的情况。普通聊天房间继续沿用原有即时缩减规则，已经退场的陪伴不会因真人离开而自动补回。

退场顺序先满足六只上限及真人入口，再兼顾玩法最少参局人数和原有陪伴数量目标。允许一局暂时六只；结算后只要仍有陪伴，总人数至多五，纯真人可以六人。捣乱德州需要至少两名愿意参局且有足够底注的玩家；未申请入座的旁观真人不计数，保留陪伴时优先保留仍能参局的陪伴。若让出入口与维持开局冲突，先让位并暂停，不能把旁观者自动扣注参局。产品示例见[陪伴小狗自动退场](../game-design/捣乱德州玩法设计.md#陪伴小狗自动退场)。

Steam 的真人容量与 UI 的六只总容量分开：扑克玩法中，房主将原生 Lobby 的成员上限设置为 `6 - 当前陪伴数`，从 Steam 入口限制新增真人，避免第七只挤掉正在打牌的陪伴。陪伴退场后再放开相应真人名额；切回非扑克玩法恢复六个真人名额。`SteamRoomData.AdmissionLimit` 表示原生真人上限，`Capacity` 仍是 UI 的六只总上限，列表人数包括陪伴。上限写入失败按间隔重试，未落实必要的容量限制时不开始／继续／重开，且不提前重置上一场筹码。Mock 使用相同容量规则。接口依据见 [Steam 的 SetLobbyMemberLimit](https://partner.steamgames.com/doc/api/ISteamMatchmaking#SetLobbyMemberLimit)。

自动退场先从房间成员和可操作对象中移除陪伴，但上一局账本在暂停期间仍完整保留。协议对历史陪伴的身份唯一性、陪伴属性与仅限结算阶段进行校验；下一次成功发牌时，规则核心同时移除退场席位、接纳申请者并扣底注。新真人获得自己的初始 1000 筹码，不继承陪伴余额；其他人的筹码和座位编号保持不变。牌桌内部身份编号单调增加，与可复用的 1–6 号座位分离；新人可以使用空座号，不能复用旧身份。下局庄家退场时，沿既定方向从原座位之后寻找入座者，连庄重置为 1。

赢自退场陪伴的筹码仍属于赢家。考虑历史三陪伴房间及后续最多六名真人各自的初始筹码，同一未中止牌桌的协议余额校验上限为 9000，单局奖池上限仍为 600；这只是合法累计金额的校验范围，不是新增筹码、补款或继承陪伴账户。若以后允许手动补陪伴或改变经济规则，必须重新设计此边界。

真人与陪伴共用 `RoomDogView` 入退场表现：进入向上钻出，退出反向下降，复用 `DesktopRiseIntroController` 的精灵动画，不增加渲染纹理或纹理回读。以客户端、布局会话和成员入房标记去重，桌宠／扑克往返及换装不重播入场。离开时立即移出交互和有效成员集合，只保留最多六个、约 0.8 秒的退场外观；隐藏、离房或销毁视图时及时清理。先缓存完整外观范围再隐藏原狗，防止入场第一帧用错误尺寸夹紧位置。陪伴房间的模拟房主已经下降时不重复播放。

房主主动请出、真人退出及换主仍遵循下面的中止保护；动画不改变权限、接管或结算规则。本轮不提供手动添加陪伴入口。

## 当前第一版中止保护

本阶段没有实现牌局存档、断线续局或换主接管牌堆。房间重新加入成功不代表恢复旧牌局。

- 参局成员退出、被请出、入房身份改变、房主改变或房间玩法改变时，中止当前牌局，不猜测遗失暗牌或继续结算。新房主可重新发起牌桌。
- 陪伴按上节规则在安全时机自动退场，不中止原场；房主主动请出当局参局陪伴，仍属于非计划成员移除，会触发中止保护。不要把自动让位的例外扩展成真人离房、被请出或换主后的牌局接管。
- 暂时收不到权威状态时，十秒后禁用本机操作并显示连接等待。房主仍使用权威时钟处理超时操作和局间推进，不因缺少动画完成回应中止。Steam 房间本身的断联恢复继续使用原流程。
- 中止后不写回单人筹码、库存、Steam Stats 或账号存档。本次临时牌桌余额不承诺断线保留；补款、离桌退款及正式经济规则不在本阶段确定。

### Mock 结算聊天

以下是当前已实现的测试能力，与正式“自动闲聊”个人设置分开控制。产品规则统一见[需求框架：自动闲聊](../game-design/Steam房间功能需求框架.md#自动闲聊)；其中“一局／本场／重开”采用[玩法术语](../game-design/捣乱德州玩法设计.md#基础设定与术语)。

- 两名模拟真人仍可保持当前回合直接 PASS 的行为；额外模拟每局结算后的聊天，用来观察气泡与手牌、牌手面板、公共牌和其他小狗的遮挡，帮助主人决定摆放位置。
- 结算公开后，每名模拟玩家每局最多发送一条短句。胜者按实际牌型说话；败者在“哎呀，就差一点！”、“下把再来！”和保持安静之间变化。用局号和模拟玩家编号确定变化，便于重复检查；不能固定宣称不存在的牌型或提前泄露胜负。并列赢家按实际并列结果处理。
- 消息走既有房间聊天与气泡显示流程，遵守字数、频率和过期规则；可稍微错开发送，但保留两只狗的气泡同时可见的情况，便于检查拥挤布局。
- 按房间、牌桌与局号去重；重置 Mock、离房、换房或结束旧牌桌时清理待发送内容，不让旧局消息出现在新房间。
- 入口仍归独立的“联机扑克”Mock 页；该需求不代表正式 Steam 玩家由客户端代发消息，也不表示正式陪伴小狗已经具备聊天功能。独立页提供“模拟玩家结算后聊天”开关，默认开启。关闭再打开不会让同一局已发送的消息重复发送。

### 正式自动闲聊

- `SettingsManager` 的 `system/auto_chat` 保存本机偏好，默认开启；系统设置“联机功能”分组提供“小狗自动闲聊”开关。设置与台词由 `InGameRoomText.csv` 提供 20 种语言，`ChatText` 可在尚未打开联机页时按当前语言取词，并处理 Godot 将 `es_419` 导入为 `es` 的资源名。牌型复用主表，“高牌”使用房间专用词条；不增加接管状态提示。个人设置只控制本人，Mock 其他模拟玩家仍由其独立开关控制。
- `PokerAutoChat` 根据房间、正式牌桌 ID 和局号管理去重与接管，不改牌局状态、筹码或小狗表情。普通续局、暂停／继续、离座／入座、桌宠往返保持同一牌桌 ID；重开才恢复新场。离房或玩法结束清理临时状态。显式关后再开释放接管，但当前结算不重播。
- `RoomPokerLobbyView` 每帧更新本机闲聊策略，不依赖系统面板是否展开。每局至多发送一句，只使用已公开的本人结算结果，等待本机展示亮牌；未参局者、正在输入、开盒／占用界面、断联、迟到结果与收牌阶段都不能补发旧台词。短句选择与 Mock 复用，败者有两种台词及安静分支。
- `RoomClient.SendChat` 仅在真正发送成功后发出 `ManualChatSent`；`SendAutomaticChat` 复用同一服务、Steam 过滤与气泡管线，不触发接管。自动发送失败不占用 Steam 发送冷却，自动台词不重试堆积。
- 手动提交恰逢自动消息的 1.5 秒冷却时，`RoomChatView` 暂存当前输入，暂时禁用输入与发送，保留取消；冷却加 0.05 秒余量后再走正常发送。实际成功前不清空输入、不计接管。取消、失焦、界面隐藏、房间上下文更换会取消待发操作；不跨房发送旧文字。手动连续发送仍保留原有频率错误，服务和接收端限速不放宽。

### 持续验证重点

- 从一起聊天投票切入捣乱德州，核对明确同意、反对、未回应与陪伴的准备差异；房主无独立准备按钮，所有状态只在同一成员列表表达。
- 切入玩法但未开局、中途入房仍为桌宠、新成员旁观后申请下一局入座、开场时未准备者入座、原成员离座和返回、往返桌宠；核对等待面板、首次分配与单次底注、原座位和余额、本人暗牌、行动进度与手动切回扑克。核对预约暂停不提示成员、真正暂停后的标题与即时离座／入座，以及暂停后由房主继续才开始下一局。
- 已下注单人局及待领奖状态下切入玩法，核对所有成员都舍弃未领取部分并禁用单人下注；已入账筹码和盲盒资产不受影响。
- 分别由房主和成员开盒，跨越本人行动、结算及下一局，核对时钟、扣注、最新状态与无阻塞回应；不因开盒额外延时或撤销准备。
- 预约暂停、取消、在结算期间预约以及暂停后继续／重开，核对两种入口同步、完整派彩、原余额／下局庄家、重开 1000 和房主坐庄、申请入座者在下一局接纳；收牌期间不能变更名单，余额不足不能绕过继续门槛。
- 陪伴打牌中陆续加入旁观者，核对当局暂时六只、结算后恢复空位、旁观不凑开局人数、申请入座后使用独立筹码、原有座位不重排及暂停结果仍能同步。核对 Steam 原生容量调整失败时不提前开局或重置筹码。
- 真人与陪伴的钻出／下降、进场中退出、快速重复入退房、模式往返及离房清理；退出外观不得继续拦截输入，网络和牌局不等待本机动画。
- 设置面板位于牌桌侧边时仍可翻牌；覆盖牌桌、开盒等占用交互时仍禁用操作。恢复操作不应依赖往返桌宠。
- Mock 双方结算气泡与小狗位置、模式往返及旧房间消息清理。此类验证仍不替代真实 Steam 双机和实际气泡布局验收。
- 自动闲聊开关保存、成功手动发言后本场静默、打开／取消／失败不接管、自动后紧接手动的发送顺序、重开恢复、关闭再打开不重播，以及设置关闭后表情仍独立显示。
