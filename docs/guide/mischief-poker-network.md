# 捣乱德州：房间参局与网络同步

玩法见[捣乱德州玩法设计](../game-design/捣乱德州玩法设计.md)，表现规则见[牌手面板设计](../game-design/牌手面板设计.md)。本阶段把已有规则核心和局间演出接入房间，保留[本机试玩](mischief-poker-preview.md)用于调节显示。

## 待实现的流程改良

2026-11-10 仅更新设计文档，没有修改代码或重新运行游戏。本节记录目标行为；后面的“当前实现”及历史验证记录不能作为这些改良已经完成的证据。

- **统一房间玩法**：捣乱德州与一起聊天、各自工作并列，接入当前玩法下拉菜单和既有投票；新房间默认一起聊天。切换玩法不等于所有成员自动参局，房间玩法、准备状态与个人桌宠／扑克显示模式分别管理。
- **整合准备 UI**：原房间成员列表同时显示准备状态与请出操作，不另建第二份名单；房主没有单独准备按钮，开始即确认本人参局。首次切入默认让明确同意者及陪伴自动准备，其他真人等待；未来规则修改后其他真人重新准备。准备区移除独立取消牌局按钮，保留本机试玩入口。
- **单人局可舍弃**：明确准备参局时可丢弃未完成单人局及未领取奖励，已入账筹码保留；不能再由 `WaitingForBet` 或待领奖状态强制阻挡。未准备者不被强制中断，也不能把这一可舍弃规则用于盲盒资产。
- **开盒与牌局并行**：恢复联机扑克中的盲盒入口，仍扣个人筹码；不能因交互占用自动取消准备。表演只限制本机可操作内容，不暂停房主权威时钟、回合超时、结算或自动续局，恢复显示时采用最新状态。
- **提前显示牌手面板**：成功切入玩法即显示无牌等待面板，桌宠本人面板同样显示。中途入房保留原显示模式，玩家手动进入扑克；不能收到网络牌局状态就无条件强制切换。本人暗牌仅在本人客户端展示，显示模式不改变传输保密边界。
- **房主预约暂停**：左侧信息面板使用“暂停／撤销／继续”（`Pause / Undo / Resume`），提示说明本局派彩后生效。预约与继续由房主权威确认并同步各端，不能只暂停房主的本地动画。保留本局结果、余额、座位及下局庄家，继续前重新校验参局与余额，不调用结束后重建牌桌的路径来变相补发初始筹码。

完整产品规则以[房间玩法与开局准备](../game-design/捣乱德州玩法设计.md#房间玩法与开局准备)、[房主暂停续局](../game-design/捣乱德州玩法设计.md#房主暂停续局)及[牌手面板的桌宠视角](../game-design/牌手面板设计.md#房间玩法与桌宠视角)为准。

实现时还需保留以下边界：

- `UiInteractionOccupancy` 继续负责局部界面的输入与自动提示避让，不能把它作为全桌是否推进的条件。未显示的本地牌局演出要正常完成必要回应或跳到最新状态，不能等待玩家关闭盲盒才解除局间阻塞；房主和普通成员分别检查。
- 现有结算完成回应属于内部表现同步，不是玩家手动确认。是否保留该屏障及具体调整另行按实现评估，但不能要求每名玩家实际看完结算或让开盒拖住下一局。
- 暂停预约与下一局提交的先后由权威状态确定；结算期间仍要处理同步和完成回应，避免把预约暂停误做成冻结网络 Tick。恢复、重复消息和已失效牌桌不能导致重复扣注、发牌或清除新预约。
- 中途入房或返回桌宠只改变视角；不能借此重新报名当局、重复获得初始筹码、清除已扣底注或延长行动时间。
- 局中更换玩法的生效时机仍待确定，不在本轮文档中将“多数通过后立即中止”固化为正式扑克规则。当前参局者退出／被请出会中止全局的限制也尚未解决。

## 当前实现的玩家流程（待按上述设计调整）

以下保留首轮已实现行为用于维护与排查，尤其是单人奖励门槛、独立参局区、自动切入扑克与覆盖层撤销准备，均须按上节改良，不能继续作为目标体验。

- 联机页的成员名单下提供“捣乱德州”区域。房主发起牌局，房主默认准备；其他真人自行点击准备或取消准备。陪伴小狗默认参局，约一秒后自动准备。
- 房主必须参局，至少两名参与者才能开始，真人与陪伴小狗均计数。未准备的成员留在房间等待，不扣底注、不获得暗牌；房主点击开始时锁定本局名单。
- 已下注的单人扑克必须先结束并领取奖励，不能用多人入口丢弃单人局。准备后暂时禁止单人扑克下注，取消准备或离房后恢复；未开局时如果本机进入需要处理的覆盖界面，会撤销准备。
- 牌局开始后自动切入扑克视图。发牌、翻牌、PASS、补牌整理、摊牌、派彩、收牌与换庄使用已有表现。正式牌局在派彩和回收结束后自动进入下一局；旧本机试玩仍保留手动“下一局”。
- 中途加入且未替换现有参局成员时，新成员显示等待入局。准备后从下一局入场，获得临时初始筹码；既有玩家的座位、余额和下局庄家保持不变，新成员追加座位。此规则不允许在看到当局暗牌后加入当局。
- 当前筹码仅为本次牌桌内存数据：初始 1000、每局底注 100。有人不足 100 时停留在结算，不自动补充筹码。房主可以在结算阶段结束牌局，再发起新牌桌；新牌桌重新使用临时初始筹码，不表示最终经济方案已经确定。
- 返回桌宠不退出牌局，也不暂停其他玩家。隐藏期间仍推进本机结算流程并回应同步，避免一个玩家切走导致全桌无法继续。离房或牌局中止后恢复单人界面。

当前入口独立管理“是否参加牌局”，尚未将捣乱德州接入房间玩法条目。后续统一玩法后仍不强迫未准备者参局；房间的聊天权限和公开权限继续由原设置管理。正式英文名称未定，当前新文案提供中文及临时英文回退，完整多语言后续统一处理。

## 同步与权限边界

- `PokerNetworkSession` 是每个客户端的牌桌端点；只有房主创建和推进 `MischiefPokerMatch`。房主掌握洗牌、未发牌堆、各玩家暗牌、行动时钟和筹码结算。当前属于信任房主的休闲牌局，不具备独立服务器级反作弊能力。
- Steam 传输使用共享 Steam 会话和回调泵，在 `ISteamNetworkingMessages` 的独立通道 7 上发送可靠消息。加入会话和收到消息都检查当前房间真人成员；不另建 Steam Runtime，也不通过 Lobby 成员数据或聊天广播暗牌。实现依据见 [Steam 官方接口说明](https://partner.steamgames.com/doc/api/ISteamNetworkingMessages)。
- 传输身份、房间代码与玩法、双方本次入房标记、牌桌 ID、命令序号、局号和修订号共同限定消息归属。发送者实际身份覆盖命令自报的玩家编号；过期、重复、错误房间、错误入房标记、非行动者及越权控制均不改变牌局。
- SteamID 字符串用于识别成员，另分配固定牌桌编号；各客户端已有的小狗本地 ID 仅用于显示映射。不能假定每台电脑的“玩家 1”是同一个人。
- 房主给每位成员分别生成快照：参局者只收到自己的两张暗牌，等待者不收到暗牌；结算后才包含本局参局者的摊牌结果。未发牌堆和未来补牌始终不发送。绿框、决胜牌强调和动画仍由各客户端按本人视角计算。
- 操作成功或拒绝后由权威状态确认。客户端有未确认操作时暂不接受第二次操作，不自动重发翻牌，避免一次点击被执行两次。消息有大小、字段、牌面与身份检查，并限制单成员命令频率。
- 发牌预留三秒，随后开始权威行动时钟；每个回合仍为十五秒。有效操作立即推动同步，牌局中另有每半秒的状态校正；空闲状态使用较低频率。
- 当前实现等待参局真人的本地结算演出完成回应后才开始下一局，陪伴与等待成员不构成该屏障；这不是玩家点击确认。完成回应绑定局号并可重复发送，不重复发奖或扣底注。正常开始下一局时，新增成员和发牌作为一次操作提交，校验失败不能改变上一局结果。开盒并行的后续调整需满足上节不被界面遮挡阻塞的要求。
- JSON 消息中的 record 构造参数与属性名属于协议。相关类型已加入混淆保留名单；修改类型时需同时检查混淆后的消息往返。

## 当前第一版中止保护

本阶段没有实现牌局存档、断线续局或换主接管牌堆。房间重新加入成功不代表恢复旧牌局。

- 参局成员退出、被请出、入房身份改变、房主改变或房间玩法改变时，中止当前牌局，不猜测遗失暗牌或继续结算。新房主可重新发起牌桌。
- **陪伴小狗被原房间规则替换退场，也属于参局成员变化，会中止当前牌局。** 因此目前“真人进入并替换参局机器人”的情况尚未做到不中断；机器人局间退场、席位继承和余额处理需要后续单独设计。普通真人房间在空位加入等待者已接通。
- 暂时收不到权威状态时，十秒后禁用本机操作并显示连接等待。房主仍使用权威时钟处理超时操作；结算后超过四十五秒仍未收齐真人完成回应，则中止牌局。Steam 房间本身的断联恢复继续使用原流程。
- 中止后不写回单人筹码、库存、Steam Stats 或账号存档。本次临时牌桌余额不承诺断线保留；补款、离桌退款及正式经济规则不在本阶段确定。

## 本机测试

使用开发启动器的“Steam 模拟环境”。进入扑克模式后，在顶部 Mock 面板的独立“联机扑克”页找到“联机牌局测试”；Steam 页仅保留盲盒、库存与平台相关测试。

1. “重置为本机房主”建立三名模拟真人的房间，并由本机发起准备；其他模拟客户端自动准备。测试玩家在联机页点击“开始牌局”。
2. “重置为房间成员”由另一个模拟客户端当房主发起准备；测试玩家点击“准备”后，模拟房主才开始。
3. 两个按钮都会重置本次模拟房间和牌局，只用于 Debug；不作用于真实 Steam 房间。模拟真人在自己的回合自动结束操作，陪伴小狗做简单合法翻牌或 PASS，不代表最终机器人策略。

切换 Steam、联机扑克或已有的本机试玩页签只切换调试控件，不重置、暂停或重新创建牌局。联机扑克页在尚未开局时即可使用，不依赖本机试玩是否运行。

Mock 端点交换与 Steam 相同的序列化消息，独立维护每个客户端的牌局视图；不再用同一个规则对象直接冒充所有真人。原“捣乱德州 · 本机试玩”仍用于牌型预设、暂停、单步与显示验收，准备或正式牌局中不能同时启动该入口。

纯逻辑检查：

```powershell
$env:NUGET_PACKAGES = "C:\Users\carlo\.nuget\packages"
dotnet run --project tests/MischiefPoker/MischiefPoker.csproj --no-restore
```

主场景自动检查入口：`--disable-steam --rooms-poker-network-main-smoke --rooms-no-capture`。使用隔离的 APPDATA、LOCALAPPDATA 和现有内存沙箱；Windows 显示驱动配合 Dummy 渲染／音频可以执行输入与节点状态检查，不能据此声称画面或听感已验收。

### 待实现的 Mock 结算聊天

- 两名模拟真人仍可保持当前回合直接 PASS 的行为；额外模拟每局结算后的聊天，用来观察气泡与手牌、牌手面板、公共牌和其他小狗的遮挡，帮助主人决定摆放位置。
- 结算公开后，每名模拟玩家每局最多发送一条短句。胜者可按实际牌型发送“哈哈，我是四条！”等句子，败者可发送“哎呀，就差一点”；不能不看实际结果便固定宣称某个牌型或提前泄露胜负。并列赢家按实际并列结果处理。
- 消息走既有房间聊天与气泡显示流程，遵守字数、频率和过期规则；可稍微错开发送，但保留两只狗的气泡同时可见的情况，便于检查拥挤布局。
- 按房间、牌桌与局号去重；重置 Mock、离房、换房或结束旧牌桌时清理待发送内容，不让旧局消息出现在新房间。
- 入口仍归独立的“联机扑克”Mock 页；该需求不代表正式 Steam 玩家由客户端代发消息，也不表示正式陪伴小狗已经具备聊天功能。本轮仅记录，暂未实现。

### 流程改良后的验证重点（尚未执行）

- 从一起聊天投票切入捣乱德州，核对明确同意、反对、未回应与陪伴的准备差异；房主无独立准备按钮，所有状态只在同一成员列表表达。
- 切入玩法但未开局、中途入房仍为桌宠、主动准备后等待下一局、参局后往返桌宠；核对等待面板、本人暗牌、行动进度与手动切回扑克。
- 已下注单人局及待领奖状态下准备参局，核对只舍弃未领取部分；未准备者、已入账筹码和盲盒资产不受影响。
- 分别由房主和成员开盒，跨越本人行动、结算及下一局，核对时钟、扣注、最新状态与无阻塞回应；不因开盒额外延时或撤销准备。
- 预约暂停、撤销、在结算期间预约以及暂停后继续，核对完整派彩、保留余额／下局庄家、未提前收牌和未重复扣注；准备或余额不足时不能绕过门槛。
- Mock 双方结算气泡与小狗位置、模式往返及旧房间消息清理。此类验证仍不替代真实 Steam 双机和实际气泡布局验收。

## 验证记录

2026-11-09：

- 规则、显示状态机与网络逻辑共 58,379 项检查通过，包括全部 2,598,960 种五张牌组合。网络用例覆盖准备权限、陪伴自动操作、私有手牌、不同本地编号、重复／过期消息、错误票据、旁观者、局间入场、完成回应、换主与成员变化，以及损坏消息。
- 新主场景专项通过房主和成员两种视角、从桌宠延迟加载扑克、真实公共牌／手臂输入、自动进入下一局、等待成员标识、桌宠往返、退出清理、准备期间禁止单人下注，以及退出后恢复单人牌局。没有追加上一轮表现的截图验收。
- Debug、ExportRelease、独立输出的 Demo 和录屏编译通过，均为零警告、零错误。程序集检查确认 Demo 和录屏不包含网络牌局、联机参局 UI 或 Steam 牌局通道。
- 混淆配置生成及实际混淆通过；使用混淆后的程序集运行网络检查并检查隔离程序集，共 103 项通过。Obfuscar 有本机旧 SDK 引用目录提示，未阻止完成或测试。
- Godot 后台检查日志有本机根证书库读取提示，未出现 C# 运行异常；检查使用 Mock，没有调用真实 Steam。
- 尚未进行真实 Steam 双机、不同版本互联、真实断网或实体多显示器验收，未打包或发布。
