# Demo 与 Playtest 参与礼物

正式版 LinkTree 提供两个独立的领奖入口。Steam 记录的对应 AppID 累计游玩满 2 分钟即获得资格。Demo 为 `5220880`，Playtest 为 `4972240`，正式版库存归属 `2583700`。参与顺序不限，玩家在购买正式版后试玩 Demo 也能回来领奖。

## 入口与奖励

- Demo 礼物面向尚未领取的玩家展示。资格待同步时提示核验，未达标时提供试玩入口，达标后点击领取整套 Demo 装扮。原 Demo 存档和庆典收集完成度不参与判定。
- Playtest 礼物仅在当前账号已核实符合条件且未领取时展示，点击领取指定装扮。两边达标可以各领一次。每份礼物的反馈结束后，该入口收起。
- 回到正式版或再次打开 LinkTree 时重新核验资格。断网或请求失败保留待核验状态，重连后允许恢复。
- 开发先用灰色软呢帽（Item 2003）与胖黑柴（Item 1002）以及两张临时 Banner。正式奖品通过礼包配方替换。Demo 庆典奖池 15 件及独立完成奖励学士帽 2034 供最终配表时核对。

## 渠道行为

- Dev 默认两项都有资格，支持从实际页面走完领取。每次启动重新获得两次独立的测试机会。
- Playtest 包查询当前 Steam 账号的真实资格。每项在本次进程内限领一次，重启可重测；允许添加占位物品，沿用现有背包规则，无需额外清理物品。资格查询必须是只读操作，否则会提前消耗 Steam 一次性发放机会。
- Release 使用相同的资格条件，各自通过固定 Steam 礼包发放装扮和独立永久回执。以当前账号的库存回执确认领取，重启和换机后仍有效。请求中断沿用平台复查机制。

## 配置与验收

资格规则为 `played:5220880/2` 和 `played:4972240/2`。Steam 文档给出了只读资格列表接口，但对带 `played` 条件的手动发放礼包仍需真实账号验证。优先使用在配置上线前已经参加过测试的普通账号，对照未参与、仅 Demo、仅 Playtest 和双资格。Playtest 和 Release 的库存配置分别发布。

本轮使用 Luban 副本导出验证策划表、游戏数据和 Steam schema。先验证 Dev 双领奖、同次运行防重、重启重领、Demo 与 Playtest 可见性及原 LinkTree 入口。Playtest 真实资格单独记录，上传由主人操作。本轮开发不制作安装包。
