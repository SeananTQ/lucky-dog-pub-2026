# 交互提示系统说明

## 概述

交互提示系统用于在扑克流程中提示玩家当前可执行的操作。系统只负责选择提示目标、维护主动与被动触发节奏，并通知目标播放动画；筹码、卡牌、小狗、手臂、奖励筹码和 Refreshment 等目标分别负责自身表现。

每个提示点使用不会跨业务复用的字符串 Key。Key 由代码登记，等待时间、重复间隔、被动冷却和优先级由 `InteractionHintConfig` 配置。

旧的全局 `GameDevelopConfig.ProactiveInteractionHintIdleSeconds` 已移除，不再参与交互提示计时。不同步骤必须分别配置等待时间，以适应下注、选牌、确认等操作所需的不同思考时间。

## 与操作说明、玩法帮助及快捷栏的分工

以下功能分别负责不同层次的引导：

- `InteractionHintController` 通过筹码、卡牌、手臂等目标动画，提示玩家当前可以点击哪里。主动等待、重复间隔和误点提示冷却由 `InteractionHintConfig` 按步骤配置。
- `TutorialManager` 只管理玩家从顶部快捷栏「操作引导」手动呼出的 SVG 操作说明覆盖层，显示后保留 2 秒关闭保护。首次进入扑克模式及闲置时均不再自动弹出；旧设置「扑克新手引导」及其 `poker_guide_overlay_enabled` 值不再参与运行判定。
- [扑克玩法帮助](扑克玩法帮助说明.md)解释正面保留、背面换掉的含义，以及为凑成牌型应保留哪些牌。快捷栏「玩法帮助」打开「怎么凑牌」，赔率表入口打开「牌型一览」；内部演示自动循环，不把示例牌演示当成牌局有效操作。
- 欢迎提示用于介绍快捷栏入口，按当前账号是否已确认提示判断，不推断玩家是否曾玩过扑克。点击「好的」后展开快捷栏 5 秒；欢迎期间允许悬停展开并直接使用功能，使用时同时确认欢迎并记录快捷栏使用。普通悬停仍按离开 0.5 秒后收起。

帮助、操作说明、欢迎提示及更高优先级覆盖层的输入协调由 `GameManager.RefreshOverlayInteractionContexts()` 统一维护，避免覆盖层点击落入牌桌。阅读帮助不会替代欢迎确认，也不表示玩家已完成操作引导。

## 快捷栏的 20 秒闲置提醒

快捷栏提醒由 `PokerQuickBarController` 独立计时，用于让玩家发现帮助入口；它与下文的目标动画主动提示是两套机制，不能把 `InteractionHintConfig` 的步骤等待时间统一改成 20 秒。

- 尚未使用过快捷栏、且未由旧档迁移为免提醒的玩家，在扑克模式连续 20 秒无有效操作后，快捷栏自动展开并保持；不自动弹出操作说明或玩法帮助。到时仍在拖窗或按住鼠标时，等该手势结束后展开。
- 有效操作复用 `InteractionHintController.EffectiveInteractionOccurred`，例如成功下注、选牌、敲桌换牌和收取奖励。它清空闲置计时、解除自动展开的保持状态，并恢复普通收起规则；未使用快捷栏时，下一轮闲置仍可再次提醒。
- 鼠标移动、移出快捷栏及空白或无效点击都不解除自动展开的保持，也不重置 20 秒计时。系统面板的打开、关闭、切换页签、滚动和控件操作同样不暂停或重置计时；系统面板可以全程保持打开。
- 欢迎提示、玩法帮助、操作说明、盲盒表演或收集进度覆盖层显示期间，暂停快捷栏闲置提醒并清空计时，返回可操作牌桌后重新计时。
- 点击快捷栏任意功能后，记录当前账号的 `tutorial_progress/poker_quick_bar_used`，停止后续闲置提醒，并将悬停热区从发现区域缩小到栏体实际高度。仅悬停、点击欢迎提示的「好的」及点击赔率表打开帮助均不算使用快捷栏；欢迎确认记录与该使用记录独立。
- 旧存档的 `NeedsPokerBasicsGuidance` 只用于新记录缺失时的兼容迁移，不再随牌型更新，也不再控制操作说明。旧引导设置开关不影响迁移或新提醒。迁移优先级、账号存储及默认关闭的 Debug 重播开关，以[《扑克玩法帮助说明》的旧档兼容和欢迎提示章节](扑克玩法帮助说明.md#快捷栏闲置提醒与旧档兼容)为准。

## 触发类型

系统区分两种互不混用的触发来源：

- `ProactiveIdle`：玩家长时间没有完成有效操作后，由系统主动播放提示。
- `PassiveMistake`：玩家点击空白或点击当前不构成有效操作的对象后，立即提示当前可执行目标。

主动提示与被动提示共享目标选择和动画互斥规则，但分别维护计时状态。

## 输入语义

一次左键点击按业务结果分为三类：

- 有效操作：推进当前流程，调用 `NotifyInteractionHandled()`；本次不触发被动提示，并重置主动等待与旧步骤的被动冷却。
- 已接收但不推进：调用 `NotifyInteractionIgnored()`；本次不触发被动提示，也不重置主动等待。
- 未处理点击：按点击空白处理，在鼠标松开后的帧结算被动提示。

点击空白触发的被动提示与长时间无操作触发的主动提示是两套独立判定。全屏交互遮罩出现时，两类判定都暂停，避免遮罩点击落入扑克区域。

## 主动提示节奏

当前提示目标满足可播放条件后，系统累计无有效操作时间：

1. 达到 `ProactiveIdleSeconds` 后播放第一次主动提示。
2. 动画结束后等待 `ProactiveRepeatSeconds`。
3. 间隔大于 `0` 时重复播放；等于 `0` 时本步骤不重复。
4. 有效操作、提示目标变化、模式切换或输入上下文变化时，重新开始计时。

某一步的主动提示一旦成功播放，该步骤后续的空白点击不再触发被动提示。重复节奏统一由主动提示控制，直到玩家完成有效操作或提示目标发生变化。

## 被动提示节奏

被动提示在未处理点击结算时尝试播放：

1. 播放当前最高优先级目标的提示动画。
2. 等待动画完全结束。
3. 再等待 `PassiveCooldownSeconds` 指定的额外间隔。
4. 额外间隔为 `0` 时，最小连续间隔就是动画自身时长。

被动额外冷却只约束同一提示步骤，不影响主动提示计时。有效操作或提示目标切换后，旧步骤冷却会被清理。

## 配置字段

`InteractionHintConfig` 包含以下字段：

- `Key`：唯一字符串 Key，必须与代码中的 `InteractionHintKeys` 一致。
- `Description`：中文维护说明，不参与运行时逻辑。
- `ProactiveEnabled`：是否允许该提示点由无操作计时主动触发。
- `ProactiveIdleSeconds`：第一次主动提示前的等待秒数，必须大于 `0`。
- `ProactiveRepeatSeconds`：主动提示动画结束后的重复等待秒数；`0` 表示不重复。
- `PassiveCooldownSeconds`：被动提示动画结束后的额外冷却秒数；`0` 表示不增加额外间隔。
- `Priority`：多个目标同时可播放时的优先级，数值越高越先提示；相同优先级按当前阶段登记顺序决定。

配置行缺失时，运行时警告并使用 `6` 秒主动等待、`0.8` 秒主动重复和 `0` 秒被动额外冷却作为容错。非正数主动等待和负数间隔会警告并按容错规则修正。

## 当前提示 Key

- `Poker.WaitingForBet.Refreshment`：准备下注时提示桌面 Refreshment。
- `Poker.WaitingForBet.BetStack`：准备下注时提示下注筹码。
- `Poker.Refreshment.UseConfirm`：使用气球打开后提示确认对号与 Refreshment。
- `Poker.Dealt.CardSelection`：发牌后提示选择需要替换的牌。
- `Poker.Dealt.DogAdvice`：发牌后提示点击小狗询问建议。
- `Poker.Dealt.HandConfirm`：发牌后提示敲桌确认。
- `Poker.Holding.HandConfirm`：调整保留牌后提示敲桌确认。
- `Poker.Settled.RewardStack`：结算后提示领取奖励筹码。

## Refreshment 特殊规则

准备下注阶段同时存在 Refreshment 与下注筹码时，通过 `Priority` 保证优先提示尚未使用的 Refreshment。

使用气球打开后，当前唯一提示目标切换为 `Poker.Refreshment.UseConfirm`。对号自带的小幅循环摇晃属于控件自身表现，不计入交互提示系统；主动或被动提示触发时，对号播放大幅摆动，Refreshment 同时播放提示动画。

点击使用气球始终可以确认使用。气球打开但尚未触发主动提示时，再次点击 Refreshment 属于已接收但不推进的操作：不确认使用、不关闭气球、不触发被动提示，也不重置主动等待。主动提示已经触发后，点击 Refreshment 也可以确认使用。

Buff 持续期间，悬停 Refreshment 只展示状态气球，不构成有效操作。点击 Refreshment 按点击空白处理，可以触发当前牌局阶段的被动提示；该状态不主动提示 Refreshment。

## 扩展规则

新增提示点时需要同时完成以下工作：

1. 在 `InteractionHintKeys` 增加带中文注释的字符串常量。
2. 让目标实现 `IInteractionHintTarget`，并区分主动与被动触发所需表现。
3. 在业务状态切换时登记目标并维护当前可用 Key 列表。
4. 在 `InteractionHintConfig` 增加同名配置行。
5. 明确目标点击属于有效操作、已接收但不推进，还是未处理点击。

Key 缺少配置时只允许使用容错继续运行并输出警告，不应静默掩盖配置遗漏。
