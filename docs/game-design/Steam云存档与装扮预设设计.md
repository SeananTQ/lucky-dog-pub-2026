# Steam 云存档与装扮预设设计

## 功能定位

Lucky Dog Rise 使用 Steam Cloud API（`ISteamRemoteStorage`）同步少量需要跨设备保留的数据，不使用 Steam Auto-Cloud 上传整个本地存档。

当前纳入 Steam Cloud 的数据只有：

- Refreshment 消耗品数量。
- 装扮搭配预设。

其他平台数据继续由各自系统负责：

- 当前筹码余额与累计全局输入获得筹码由 Steam Stats 和本地累计账本负责。
- 首轮奖励序列已经完成的最高稳定进度由 Maximum 类型的 Steam Stat 负责；旧 Steam Inventory 里程碑回执只作为兼容证据。
- Steam 装扮所有权由 Steam Inventory 负责。
- 扑克牌局、Buff 剩余局数、当前桌面 Refreshment、New 标记、设置和盲盒精确运行态不进入 Steam Cloud。

Steam Cloud 只提供玩家便利性，不是服务器权威经济系统。游戏允许客户端可信，目标是降低正常玩家换设备或重建存档时的数据损失。

## AppID 后台要求

每个 AppID 必须分别完成 Steam Cloud 配置：

- 设置单个玩家的字节配额和文件数量配额。
- 保存并发布 Steam Cloud 配置。
- Playtest AppID 与正式 AppID 的配置互不替代。
- 功能在对应 AppID 生效并经过验证后，可以在商店“游戏基本信息”的支持功能中勾选“Steam 云”。

游戏通过 Steam Cloud API 主动读写文件，因此无需配置 Auto-Cloud 路径。

## 账号隔离

Steam 云端文件由 Steam 按 AppID 和 Steam 账号隔离。本地镜像也必须按已验证的平台账号隔离，禁止使用跨账号共享的 `PlayerPrefs` 或公共目录进行合并。

Steam 账号的本地根目录为：

`user://accounts/steam/<SteamID64>`

其中云存档本地镜像为：

- `consumables_v1.local.json`
- `outfit_presets_v1.local.json`

游戏必须在确认 SteamID 后才能创建 `AccountStorageContext` 和加载玩家数据。运行过程中检测到 Steam 账号变化时，应停止平台写入并退出，不能继续沿用旧账号的本地镜像或运行状态。

## 消耗品云存档

云端文件名为 `consumables_v1.json`。

只同步满足以下条件的物品数量：

- `ItemType = Refreshment`
- `AcquisitionType = RefreshmentBlindBox`

不会同步：

- Lucky Deal Buff 剩余局数与参数快照。
- 当前摆在牌桌上的 Refreshment。
- Refreshment 的 New 标记。
- Steam Inventory 装扮和 Initial 基础物品。

首次建立云端基线时，本地与云端缺少共同版本基线，因此按每种消耗品的较大数量合并，优先避免已有物品意外丢失。基线建立后，正常修改按整个文档的 `UpdatedAtUnixMilliseconds` 执行较新版本优先；时间相同但数量不同的异常冲突仍按每种物品较大数量收敛。

玩家获得或消耗 Refreshment 后，系统立即更新账号专属的本地镜像，并在 3 秒防抖后写入 Steam Cloud。Steam Cloud 暂时不可用时保留本地数据，每 15 秒重试；正常退出时额外尝试刷新。

## 装扮预设

云端文件名为 `outfit_presets_v1.json`，当前固定提供 9 个槽位。

交互规则：

- 点击空槽位，将当前装扮保存到该槽位。
- 点击已有预设，应用该预设，不覆盖槽位内容。
- 已有预设不能直接修改；玩家需要先应用、删除，再保存到空槽位。
- 点击删除按钮立即删除，无需二次确认。
- 槽位中只显示实际保存的道具图标，不为未穿戴部位保留空位。
- 背包中隐藏的物品不在预设图标列表中显示。
- 预设图标使用背包品质边框，但不显示 New 和装备中标记。

预设只管理玩家能够在背包中搭配的装备。`Arm` 由系统设置独立控制，不写入预设，也不会在应用预设时被更改；普通本地存档仍需保存手臂设置。

每个槽位独立使用最后写入优先规则。删除会保存为墓碑记录，避免另一台设备上的旧预设在合并后复活。时间完全相同时，删除优先；其他冲突使用确定性排序，确保两端最终得到相同结果。

应用预设前必须验证每件道具：

- 道具仍存在于当前数据表。
- 道具类型与预设槽位匹配。
- 当前 Steam 账号确实拥有该道具。

任何一项不满足时，该预设不应用，也不能只应用其中一部分。

## 重建存档后的装扮恢复

正常启动已有本地存档时，云端预设只恢复预设列表，不主动覆盖玩家当前装扮。

新建、删除后重建或替换无效本地存档时，系统执行一次自动恢复：

1. 等待装扮预设完成本地与 Steam Cloud 合并。
2. 等待 Steam Inventory 完成可信同步。
3. 按槽位顺序检查非空预设。
4. 跳过当前账号缺少所需道具的预设。
5. 应用首个真正可用的预设并立即写入本地存档。

这里的“首个”是首个可用槽位，不固定为 0 号槽位。前面的槽位可以为空，也可以因为当前账号缺少道具而不可用。

如果完全没有预设，或所有预设都不可用，系统保留新存档的默认装扮并结束本次自动恢复。后续游玩过程中不会因为网络恢复或获得新道具而突然自动换装。

## 故障与降级

- Steam Cloud 不可用时，游戏继续使用账号专属的本地镜像，不阻塞启动。
- 云端 JSON 损坏或版本不支持时，不覆盖当前本地数据，并等待后续重试或人工处理。
- 预设引用未拥有道具时，预设列表可以保留，但应用操作失败且不改变当前装扮。
- 玩家在 Steam 客户端中关闭该游戏的云同步后，云端读写不可用，本地游戏功能仍可继续使用。

## 当前验收状态

Playtest AppID 已完成 Steam Cloud 配置、发布和客户端实测：

- 删除账号本地存档后，Refreshment 消耗品数量可以从 Steam Cloud 恢复。
- 删除账号本地存档后，装扮预设列表可以从 Steam Cloud 恢复。
- 新建本地档会正常触发新手流程，证明恢复内容不是旧本地总存档残留。
- Steam Inventory 物品与本地消耗品继续保持各自的数据边界。
- 不同 Steam 账号使用独立的本地镜像，没有复用另一账号的预设数据。
