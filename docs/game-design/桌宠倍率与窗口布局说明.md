# 桌宠倍率与窗口布局说明

## 功能范围

桌宠大小只影响桌宠生态，不影响扑克内容和系统功能面板。受倍率控制的内容包括小狗、Counter、普通盲盒提示气球、桌宠盲盒表演和启动 Rise 动画。

系统功能面板保持 420×600 的设计尺寸，不随桌宠倍率缩放。

## 五档倍率

设置页 Display 分组提供五档刻度滑条：

- `0.5x`：相对当前默认大小为 0.5 倍，小狗最终使用原素材的 12.5%。
- `1x`：默认档位，小狗最终使用原素材的 25%。
- `2x`：小狗最终使用原素材的 50%。
- `3x`：小狗最终使用原素材的 75%。
- `4x`：小狗最终使用原素材的 100%。

设置只持久化整数档位 `0～4`。设置缺失、类型错误或数值越界时回退到默认档位 `1x`。

## 应用与确认

玩家改变滑条后，桌宠不会立即变化。只有候选档位与已确认档位不同时，“应用”按钮才可用。

玩家点击“应用”后，系统临时应用候选倍率并显示十秒确认遮罩：

1. 玩家选择“保留”时，候选档位写入 `settings.cfg`。
2. 玩家选择“恢复”或倒计时结束时，恢复应用前的档位、窗口位置和任务栏吸附状态。
3. 确认期间关闭系统面板或切换模式时，同样执行恢复且不写入候选档位。
4. 候选档位不会提前写盘；确认期间异常退出后，下次启动仍读取上一次已确认档位。

## 统一缩放

场景中的 `DogArea` 继续保留 0.25 基础缩放。运行时对桌宠设计坐标应用相对倍率，使以下内容使用同一套倍率与锚点：

- `ContentA` 中的小狗、`TaskBar`、`WindowSize` 和 `DesktopBlindBoxRevealAnchor`。
- 桌宠 `CanvasLayer` 中的 Counter。
- `Bubble` 层中的普通盲盒提示。
- `DesktopBlindBoxRevealOverlay` 整层盲盒表演。
- `DesktopRiseIntro` 的裁切、爪子、舌头和前景层。

交互命中区使用缩放后的窗口坐标。小狗、Counter、盲盒提示和盲盒表演的可见交互区域应可点击，外围透明缓冲区继续穿透。

## 清晰度规则

Counter 和盲盒提示中的字体使用与桌宠倍率匹配的字体 oversampling，避免先低分辨率栅格化再整体放大。

圆角矩形继续使用 Godot 样式资源，但抗锯齿宽度按最终倍率补偿，避免高倍率下边缘发虚。

盲盒 Loading 图标使用 `DPITexture` 导入 SVG。桌宠倍率变化时更新该桌宠实例的 `BaseScale`，由 Godot 按需要重新栅格化；不会在旋转动画的每一帧重复栅格化。0.5x 使用 1x 栅格精度即可。

## 胖窗口尺寸

桌宠 A 区的基础设计尺寸为 265×235，运行时尺寸为：

- 宽度：`ceil(265 × 桌宠倍率)`。
- 高度：`ceil(235 × 桌宠倍率)`。

胖窗口左右各保留一份系统功能面板宽度。底部保留一份系统功能面板高度；顶部缓冲至少为一份系统功能面板高度，并会根据桌宠盲盒表演向上的实际范围继续增大，避免 3x、4x 表演被宿主窗口裁切。

3x、4x 始终保持玩家选择的真实倍率。屏幕空间不足时允许透明宿主窗口或桌宠上部超出工作区，不自动缩小桌宠。

## 任务栏吸附

自动吸附任务栏只在桌宠模式生效，扑克模式不得吸附。

`ContentA/TaskBar` 是小狗与 Windows 任务栏上沿的设计锚点：

- 桌宠已吸附时，Windows 任务栏高度变化后，锚点跟随新的任务栏上沿。
- 桌宠未吸附时，Windows 任务栏高度变化不得改变玩家最后一次拖拽确定的位置。
- Windows 可能先重排超大的透明宿主窗口，再向 Godot 暴露新的工作区。当前实现会在下一游戏帧恢复未吸附桌宠的位置；极少发生的一帧瞬时闪动属于已接受边界。

## Counter 布局

只有同时满足以下条件时，Counter 才按 Windows 任务栏高度自动居中：

- 玩家开启“自动吸附任务栏”。
- 桌宠当前确实处于任务栏吸附状态。
- 玩家开启“Counter 在任务栏居中”。

桌宠未吸附、关闭自动吸附或关闭 Counter 居中时，Counter 使用场景中手调的默认位置和高度。

Counter 尺寸严格跟随桌宠倍率，不因任务栏高度不足而缩小。与舌头冲突时，通过移动 Counter 避让，允许 Counter 超出任务栏范围。

## 系统功能面板避让

系统功能面板使用九宫格槽位避让屏幕边缘。桌宠模式和扑克模式分别维护槽位优先级；所有槽位都不可用时，覆盖在 A 区中央作为兜底。

桌宠模式的 4 宫和 6 宫使用 `TaskBar` 锚点作为面板底边，即面板底部与小狗的任务栏吸附下沿对齐。不得使用整个缩放后 A 区的底边，否则倍率越大，侧边面板越容易被推到屏幕之外。

## 验收边界

功能收束时已完成当前开发机器上的五档视觉、交互和任务栏行为测试。后续 Playtest 仍需覆盖：

- Windows DPI 100%、125%、150%。
- 不同 DPI 的多显示器之间拖拽。
- 不同分辨率和不同任务栏高度。
- 五档下的启动 Rise 动画、普通盲盒提示、完整桌宠开盒表演和点击穿透。
