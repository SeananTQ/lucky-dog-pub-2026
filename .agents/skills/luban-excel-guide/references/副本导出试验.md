# 副本导出试验

目标是在正式 Excel 合并前，用可追溯的副本继续完成当前开发任务。试验启用条件见 [SKILL.md](../SKILL.md)。Demo 与 Playtest 参与礼物任务已实测 Excel MCP 修改副本、Luban 导出、同步到游戏和 Godot 领奖回归。试验仍默认关闭。

## 准备本次输入

1. 按主技能的工作副本位置约定选定任务目录。首次准备试验输入时，在工作区为该任务建立子目录。从项目当前的 `luban-excels` 复制 `luban.conf`、`defines/` 和整个 `xlsx/` 到该目录。保留这套输入的原始快照，以便比较并合回本次修改。
2. 按下方命令先从原始快照导出一份基线，再在独立的工作目录中用相同结构准备本次输入。读取目标工作表的最新表头、字段备注和同类行，按业务 ID 定位。涉及新字段、奖励类型或选号时，先按主技能的填表和 ID 规则，用本次真实数据走一遍填法。只把查完仍有分歧的设计或选号留给用户决定。
3. 将要改的工作簿另存为带“副本”或 `copy` 的文件，如 `Items 副本.xlsx`。用 Excel MCP 编辑这份文件，核对改动的工作表、业务 ID、字段及旧值和新值。将编辑完成的文件复制到这次的工作目录，使用 Luban 期望的名字，如 `xlsx/Items.xlsx`。`__tables__.xlsx` 的 `input` 列已经按 `工作表@工作簿.xlsx` 指定来源，无需为文件改名去改表清单。正式源表始终由用户决定何时合回。

## 导出并核对差异

分别在基线和本次工作目录中运行同一条 PowerShell 命令。两个目录各自包含 `luban.conf`，因此各自的 `output-data/`、`output-code/` 也都留在试验目录内。

```powershell
dotnet 'G:\Workspace\godot-project\lucky-dog-pub-2026\luban-excels\Tools\Luban\Luban.dll' -t all -d json -c cs-simple-json --conf ./luban.conf -x outputDataDir=output-data -x cs-simple-json.outputCodeDir=output-code
```

检查两次导出的退出码，成功后比较两份结果。按表、业务 ID 和字段核对 JSON，同时核对生成的 C#。纯数值改动通常只影响对应 JSON。遇到额外变化时先查原因，修正副本后重新导出。

## 同步、验证与交付

- 将本次已核对的 JSON 差异同步到 `lucky-dog-rise/Data/Json/`，C# 差异同步到 `lucky-dog-rise/Scripts/DataTables/`，保留 Godot 的 `.uid`。同步前核对目标文件与基线；若目标已有独立改动，先查清差异，避免整份覆盖。只应用本次任务涉及的文件，不把试验输出目录整体覆盖到游戏。
- 接着完成原开发任务，从受影响的游戏入口验证具体效果。交付时写明改了什么、实际验证到哪一步，以及已编辑副本的路径，保留副本供验收和合回。
- 正式表合回前，用正式表重新导出会恢复旧值。用户决定合回时，先核对正式表自取快照后是否又有修改，按本次差异合并。一次试验通过后，后续任务仍需单独启用试验。
