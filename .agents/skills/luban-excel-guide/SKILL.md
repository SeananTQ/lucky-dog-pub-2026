## 概述

当接到编辑Excel的任务时，请使用Excel MCP来编辑.xlsx文件，并遵守以下事项。


## 副本导出试验（默认关闭）

只有用户针对当前任务说“表格任务交给你”，或明确要求本次试用副本导出流程时，才读取并执行[副本导出试验](references/副本导出试验.md)。授权仅对当前任务生效。讨论、引用口令或编辑本技能均不触发试验。普通配表任务沿用原有副本协作方式。

## 铁律

- 修改`xlsx`文件时，只允许修改文件名中包含`副本`、`copy`、的`xlsx`文件。其目的是为了程序出错导致xlsx源文件损坏，最终用户会自行合并到正式的xlsx文件中。
- **不要手改 Luban 生成代码**：如果生成的 `.cs` 缺字段或类型不合适，默认由用户在 Excel/配置源里调整后重新导出；明确试用时可在工作副本中完成该步骤。不要直接修改生成物
- 不要使用Python脚本直接修改xlsx文件，如有必要，则必须先与用户进行商议

## 规则

- `luban-doc-main/`这个文件夹是官方文档，当你有不确定的东西时可以查看来确认细节
- 文档中会有一些图片链接，但有时你的模型可能不具有看图能力，此时你需要向用户请求协助
- 用户提供的xlsx或者csv中，除了表头之外，其他行的**第一列可能是注释**，你要留意这一点，避免后面看错列。即**A 列是注释列，不是备注列**：它通常用于临时用 `##` 屏蔽整列或整行，语义接近代码里的 `//`。不要把说明文字、策划备注、字段解释写到 A 列
- **Luban 4 列偏移**：数据行的第 A 列（注释列）应留空，ID 从第 B 列开始写入。填错会导致所有数据向左偏移一列
- **用户交办新任务时先 re-read**：用户可能在上一个任务完成后手动编辑过 Excel（如插入/删除行）。每次用户提出新的填表需求时，应先用 `excel_describe_sheets` 或 `excel_read_sheet` 读取最新状态，再计算行号。同一轮连续写入过程中缓存是可靠的，无需反复读取

## 填表协作习惯

- **先理解现有表头再动笔**：编辑前读取目标 Sheet 的前几行，确认注释列、字段名行、类型行、中文名行、备注列分别在哪里。不要凭记忆假设列号
- 用户不擅长英语，你需要帮助用户创建正确的英文字段名，一些表里已存在的字段名如果会产生严重歧义，需要为用户指出。
- **英文字段名要稳定、准确、少歧义**：不要逐字硬翻中文，优先使用业务含义清楚的英文名。字段名应表达“这列数据是什么”，避免表达“程序会怎么处理它”
- **中文字段名用策划视角**：第 4 行一类的中文名应尽量直观、短、好维护，避免程序味过重。优先写用户能直接理解和填写的名字，而不是实现细节
- **备注写到真正的备注列**：如果表里已有“备注”“说明”等列，字段解释和填表示例应写在那里；如果没有，要先询问用户是否需要新增，不要随手占用注释列或数据列
- **善用枚举名称**：避免使用1、2、3等数字作为枚举值，优先使用枚举名称，降低用户维护成本，Luban在生成Json时会自动映射。
- **建表时优先减少因马虎、眼花、手滑而出错的情况。** 拿一条真实数据试填，找出容易漏填、看错列或误选的地方，再决定字段怎么放。比如同一份礼包拆成“首件”和“附加物品”，只填一栏也可能正常导出，却会少发奖励。把这份礼包的全部物品列在同一个列表里，就消除了漏填另一栏的机会。
- **字段名和备注要让人能直接判断怎么填。** 布尔字段写清勾选后的效果，例如“未满足领取条件时隐藏本条”，同类入口都能用。若约定 0 表示无，就写“填 0 表示无”。普通顺序枚举按已有显式数值顺排，新增成员接在本组末尾，已有值保持稳定。
- **废弃字段要标清楚**：如果发现字段已不再生效，应建议改名、备注或用注释列屏蔽，避免用户继续维护无效数据

## ID 分配

- 各子段和业务表可以有不同的选号习惯。先核对“这个 ID 能不能用”，再判断“为什么选这个 ID”。分配 Steam ItemDef 时，从当前导出的 `lucky-dog-rise/Data/Json/tbsteamitemdefidrange.json` 读取对应子段的范围、用途、说明和示例，再核对候选 ID 的实际占用及关联。其他业务 ID 查各自的表和已有约定。
- LinkTree 的回执和礼包优先与入口末三位对齐。例如入口 `1012` 配回执 `501012`、礼包 `601012`，留出空号方便以后按入口找全套。此约定只适用于分段表中对应的两个子段；代码按表中实际引用关联。遇到占号、预留或已发布的旧号，保留原有含义。
- 参考历史排法时，只比较同一用途的有效记录，剔除已确认的测试墓碑。检查占用时仍把墓碑视为已占用，永久冻结的子段整段跳过。按该表的备注、分段说明或历史记录核实状态；仅凭跳号、空缺或编号不合规律，不能断定某个号是墓碑或可用。
- 沿用已写明的规则时可直接填。遇到只知道合法范围、段内排法有多种解释时，查对应字段备注和可用的历史决定。仍有分歧，带着候选号、各自理由和一条实际示例询问用户。新确认的规则应在对应子段或字段已有的说明、示例处写清适用范围、选择理由和一个例子，随本次副本交付。查不到的历史动机保留为未知。
