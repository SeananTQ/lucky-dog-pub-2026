# 目录与候选管理

默认工坊根目录：`G:/Workspace/LuckyDogRise_DigitalDrops/HatDesignStudio/`。主人指定其他位置时优先遵循；目录不存在时创建。若写入权限受限，走正常授权流程，不静默回退到游戏项目堆放图片。

- `00_参考资料/内部参考/`：项目原画、游戏内截图、咱们生成的方案；生成候选须注明认可范围，不能自动当作画风正例。`00_参考资料/外部参考/`：竞品截图、现实帽子照片及其他项目资料。按内容来源分类，不按上传者分类；主人提供的项目小狗图仍属于内部参考，主人提供的 Bongo Cat 截图属于外部参考。记录原始来源与参考职责，外部参考不覆盖项目画风，不替换正式素材。
- `01_生成批次/YYYY-MM-DD_<主题>/`：每批包含 `候选图/待点评/`、`候选图/已认可/`、`候选图/需修改/`、`候选图/未采用/`，以及 `提示词/`、`评审/`、`预览/`。使用稳定编号，例如 `B01-a02`；图片、prompt、metadata、review 使用同一编号。
- `02_已选方案/`：按 `第一档/`、`第二档/`、`第三档/`、`档位待定/` 收录主人明确认可的方案副本。保存来源批次、认可范围及原图哈希，不把 AI 初评当作主人认可。品质未定则放档位待定。
- `90_历史归档/hat-production/`：旧项目输出的只读用途副本，保持历史结构与原文；旧绝对链接可能仍指原项目。初始归档没有删除旧目录。早期 hat-generation-lab 尚在原项目，不假称已全部迁移。
- `候选索引.csv`：记录当前纳入管理的编号、主题、美术档位、候选状态、相对路径与认可范围；历史归档不自动批量判级。

状态与三档品质分开。新图默认待点评；主人明确认可且无待办修改才进入已认可，提出修改则需修改；AI 判失败的未采用候选保留原图与原因，并标明结论来源。每次改变归类时同步 metadata 与索引，不覆盖旧图；先核实源和目标路径位于工坊内部，再进行移动。不要为状态变化删除失败记录。

已选方案是供主人方便取用的可追溯副本，不是正式游戏素材。部分认可要写明范围，如“创意与画风认可，佩戴未验证”。改图一律新编号，原先认可不自动继承为新版认可。

在工具默认目录完成生成后复制到工坊，检查哈希。逐字提示词、输入来源、调用次数、AI 初评和主人反馈一并留档。预览可等比缩放和排版，不能改原始图像来伪装生图结果。仓库仅维护规则、Skill 和模板；不自动 Git 提交新规则或图片。
