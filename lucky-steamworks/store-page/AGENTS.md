# Steam 商店页文字与正文媒体工作规则

本文件约束 AI 在 `lucky-steamworks/store-page/` 内的工作。目录结构和手动下载方法见同目录 `README.md`。

## 管理范围

- 维护“关于此游戏”（长描述）、“简介 / 概述”（短描述），并补齐 Steamworks 描述字段提供的 30 种语言。
- 维护描述正文实际引用的插图、动图、短视频及其源文件，包括正文展开后可见的媒体。
- 不管理商店页顶部的宣传视频、截图、胶囊图、库资产，也不处理构建、审核或 Steam 库存业务。

## 权威来源与共用文案

- 主人指定的最新 Steamworks 网页内容为权威；主人手动下载并指定的本地化 JSON 是对应网页内容的核对依据。
- 优先读取 `text/downloads/` 内主人提供的文件，无需每次重新浏览 Steamworks。不要仅凭文件名或文件修改时间推断主游戏、Demo 或内容的新旧。
- 本地 Markdown 与权威内容冲突时，以权威内容修正文档；`text/about/archive/` 和目录外历史准备文档不作为当前定稿。
- **Demo 商店页与正式版商店页共用一套长描述和短描述**，不建立两套维护文案，也不自行添加 Demo 专属介绍或删减版本。
- 共用文案不等于共用应用身份。各页面的原始导出和待上传 JSON 保留各自的 `itemid`；商店页编辑记录 ID 不是 AppID，不能直接将另一个页面的 JSON 当作当前页面导入。

## 多语言文案的总体方法

- 翻译前先拆解每一段在商店页中的作用，再用目标语言重新写成当地玩家会自然读到的文案。不要按中文句序逐词替换，也不要把“语法正确”当成“已经地道”。
- 每个语言版本都同时承担三项任务：准确介绍产品、营造温柔陪伴感、在目标语言中像原生广告文案。三者冲突时，先守住产品事实与核心情感，再调整句式和修辞。
- 可以为自然度改变语序、合并或拆分句子、删减不重要的列举、替换当地不存在的修辞；不能改变陪伴关系、玩法规则或奖励含义。
- 翻译完成后要反向检查“玩家会理解成什么”，而不只是核对字面意思。尤其检查主客体是否倒置、地点修饰是否产生歧义、代词是否生硬、广告语是否像命令，以及盲盒、扑克、幸运点数是否被误解成真实货币博彩。
- 文案应让玩家感到被接纳和被陪伴，而不是被要求先照顾、培养或取悦小狗。小狗可以成长和获得装扮，但情感前提是它愿意安静陪在玩家身边。

## 正文中的游戏名、角色名与亲昵称呼

- 这些称呼原则来自 2026-09-18 Codex 会话《合并美术改造分支并打包》中关于公告的讨论，并已整理在项目 `lucky-dog-announcement` Skill 的“名称和拟人化称呼”一节。商店正文沿用其按上下文判断的原则，不机械套用公告的格式和流程。
- 翻译中文“小狗”之前，先判断它指的是正式游戏名、游戏简称或品牌拟人化称呼、游戏里的角色，还是一句话中的亲昵代称。不能看到“小狗”就一律翻成 `little dog` 或 `puppy`。
- 正式游戏名按各语言已经确认的名称使用，外语通常保留 `Lucky Dog Rise`；指游戏简称、品牌拟人化称呼或已命名的小狗角色时，使用 `Lucky Dog` 等已确认的称呼。这里的“小狗”可以像“小招”“小度”一样承载品牌身份，不只是描述动物体型或年龄。
- 表达委婉请求、感谢和亲近感时，可以按语境使用 `puppy`、`little dog` 或目标语言自然的亲昵代称，不要求每处都用专名。日语 `この子`（这孩子）可用于团队或叙述者亲近地称呼角色，但不固定为品牌自称；先判断是谁在说、称呼谁，不硬造当地昵称。
- 例如“感谢大家陪小狗一起成长”若承接游戏迭代与玩家反馈，可以写成 `Thank you for helping Lucky Dog grow.`，保留品牌拟人化与共同成长的关系；也允许根据具体上下文换用更自然的亲昵称呼。外语称呼的关键取舍附中文回译及简短说明，让主人能够判断。
- **正文称呼与末尾关键词段落承担不同职责。** 前面的正文按语境准确表达产品、身份和陪伴关系；正文媒体之后的关键词段落专门承担“蹭热词”和搜索词覆盖，先研究当地用户可能搜什么，再创作文案。不能用正文的称呼统一规则把已选关键词都替换成 `Lucky Dog`，也不能以正文已经译出“小狗”为由认为关键词任务完成。

## 开头两句与居中排版

- “关于此游戏”的开头两句是一个完整的揭示结构：第一句回顾玩家可能养过的其他桌面伙伴，第二句转折并揭示“这一次是一只小狗”。转折用于揭示这位新伙伴的身份，不暗示玩家需要替换或放弃已有桌宠。不要把两句翻成彼此无关的产品说明。
- 第一行必须尽早明确事情发生在电脑、桌面或屏幕上。若只写“你也许养过猫、鱼”，再把“在屏幕上”拖到句末，某些语言会先被理解成现实中养宠物。
- 第一段允许列举猫、鱼及其他奇妙的小伙伴，但列举服务于节奏，不是必须逐项保留。版面过长时，优先删掉“小虫子”等次要项目，再把剩余项目概括成“其他奇妙的小伙伴”；不要为了逐字完整破坏居中后的轮廓。
- 第一段负责铺陈，视觉上可以占一至两行；第二段负责落点，应明显更短，最好保持一行，并尽量把“小狗”留在句尾或语义重音处。避免第二段塞入游戏类型、功能或额外形容词。
- 居中文案不能只看字符数。中文、韩文、拉丁字母以及不同字体的实际宽度差异很大；同样数量的字符不等于同样宽度。应以 Steam 实际渲染结果判断，重点观察换行位置、左右延伸、是否出现孤零零的尾词，以及两段之间是否形成自然的“铺陈—落点”。
- 调整宽度时依次使用：删减次要列举、换成更短的当地常用词、重排语序、合并近义成分。不要通过生硬缩写、残缺句或不自然的同义词强行卡长度。

## 正文与“配得感”

- 正文的核心心理方向是：玩家不需要先证明自己、付出劳动或成为“合格主人”，也值得拥有一只安静陪伴自己的小狗。文案中的幸运与温柔是主动来到玩家身边的。
- 最关键的一句是“能遇见你，是小狗最大的幸运”。各语言可以自由改写，但主客体绝不能翻反：幸运的是小狗，因为它遇见了玩家；不是玩家因为得到小狗才幸运。
- 这句话不是普通的可爱夸奖，而是整篇文案建立配得感的支点。目标语言若直译显得生硬，可以改成“这场相遇是它最大的幸运”“遇见你是它一生中最幸运的事”等自然表达。
- “它不会打扰你，也不会催促你”用于解除负担感。目标语言中应表达它不索取、不督促、不会妨碍工作，而不是暗示玩家必须持续照料、回应或完成任务。
- “工作、休息、游戏”是陪伴场景，不必机械对应“摸鱼”。目标语言没有自然对应词时，使用“短暂休息”“喘口气”“放松一下”等当地表达。
- 键鼠输入、幸运点数、扑克小游戏、盲盒与装扮段落负责说明真实玩法。情感化措辞不能遮蔽操作事实，也不能添加未确认的社交、养成、付费或奖励机制。
- 正文最后的装扮段落可以表达“小狗越来越特别、越来越属于玩家”，但不要变成所有权宣言或物化语气；应落在“更像只属于你们的伙伴”“更有你的印记”等亲密关系上。

## Slogan 的两层含义

- 中文 Slogan“生活忙忙碌碌，小狗缝缝补补”同时包含两层意思，翻译时两层都要存在：表层是生活在忙碌中磨损、散开或出现裂缝，小狗把它一点点缝补起来；深层是玩家的日常疲惫与情绪缺口，被小狗安静的陪伴温柔修复。
- 不要只翻出“生活很忙，小狗很可爱”，那会丢失“修补”；也不要只翻成小狗真的在做针线活，那会把情感隐喻降成具体动作。
- 优先寻找目标语言中与“磨损、脱线、裂开、补好、缝合”有关的自然隐喻或惯用表达。没有合适对偶时，可以拆成两个短句，但仍要形成“生活出现损耗—小狗将其修好”的因果或回应。
- Slogan 应有口号感：短、可独立成立、读起来有节奏，最好保留两拍或两分句结构。可以牺牲字面对称来换取目标语言的韵律，不能为了押韵制造陌生词组或改变含义。
- Steam 页面已经通过居中、颜色和留白把它表现成 Slogan 时，默认不依赖引号制造口号感，也不强求句末标点。是否使用当地引号或句号，应服从整页视觉风格，而不是照搬中文书名号或引号。

## 结尾的首尾呼应与邀请语气

- 正文结尾以“在你忙碌的电脑桌面上，也留一个位置给这只小狗吧！”为语义与语气基准，必须回扣开头玩家可能已经拥有的猫、鱼或其他桌面伙伴，收束整段介绍。
- 受众切入点来自主人的观察：Steam 上狗题材桌宠较少，部分玩家其实更想养狗，却因缺少合适选择而养了 Bongo Cat。开头揭示“这一次是一只小狗”，回应的是这份对狗的偏爱；结尾再让玩家想到“其他小伙伴已经有位置，也别把这只小狗落下”。翻译应理解这层背景，不必把市场观察直接写进商店正文。
- 邀请关系是“继续喜欢和养着已有的桌宠，也顺便让这只小狗加入陪伴”。必须保留“也、一起、再添一位”的含义，不能翻成让玩家放弃已有桌宠、改玩本作，或要求它成为玩家唯一的桌面伙伴。
- 语气必须略带“委屈求全”、试探和不愿添麻烦的感觉，让邀请成为小心地请求一点位置，避免玩家感到被命令。这是翻译要求，不能降为可有可无的修饰；理想感觉接近“能不能也给它留个小角落呀”“只要一点点位置就好”。这份委屈可以触动玩家的心软、不忍落下小狗和轻微内疚感，这是主人有意选择的情感切入点，不能以“避免内疚感”为由删淡；同时保持温柔与分寸，不要卑微到令人不适。
- 含义与语气要同时成立：“也”“一起”等表达加入已有伙伴的关系；“小小的”“一点点”“只要”或当地自然的委婉句式表达不敢要求太多。按目标语言自然组合，不机械堆叠示弱词，也不规定必须出现几个词。
- “角落”既是实际屏幕位置，也是关系上的小小容身之处，表达小狗只想轻轻加入、不要求独占玩家的桌面和注意力。尽量保留这一双关，不要随意改成“下载它”“带它回家”而切断首尾呼应。
- 结尾要有邀请小狗留下来的意味；仅表达“也许还有位置”的猜测，不一定能传达小心请求的感觉。反向释义时应检查玩家是否读到“也让我陪着你，好吗”，而非仅知道屏幕可能还有空位。
- 避免强硬的购买号召和命令式安置，但不要仅凭句式或标点判断语气。中文的“吧！”可以是温柔邀请；目标语言可使用自然的委婉请求、疑问句或柔和的陈述式邀请，不强求问号，也不因感叹号就判定不合格。最终以当地玩家读到的请求分寸为准。

## 短描述的压缩与预览

- 短描述要在有限空间内完成四件事：桌面小狗陪伴、工作/休息/游戏场景、与小狗打牌并观察表情、开启盲盒收集装扮并建立两者的小窝。空间不足时可以压缩连接语，但不要只剩功能清单。
- Steam 给出的字符建议只能作为初筛。中文字符通常比拉丁字母占用更宽，越南语、德语、法语等又会因单词长度产生不同换行；最终标准是实际页面显示宽度和行数，而不是让所有语言拥有相同字符数。
- 短描述应优先控制在 Steam 建议范围内，并通过实际预览确认。若字符数合规但比其他语言多出一两行，仍需继续压缩；若略有差异但版面自然，则不必为了数字一致破坏语句。
- 压缩顺序为：删重复形容词、合并场景列举、缩短过渡句、用目标语言更紧凑的自然结构。最后才考虑删玩法信息。
- 预览测试应使用对应 Steam 语言参数打开页面，例如测试分支页面配合 `?beta=1&l=<language>`；检查长描述开头的居中换行、Slogan 和结尾相对插图的位置，以及短描述在右侧信息区的实际行数。

## 地区变体与本地化边界

- Steam 将部分语言变体作为独立选项时，应按独立文案处理，而不是只替换一个名词。当前尤其包括 `Español (España)` 与 `Español (Latinoamérica)`、`Português (Portugal)` 与 `Português (Brasil)`。
- 地区版本需要同时检查称呼体系、代词、动词变位、电脑相关术语、标点、亲昵程度和广告口吻。例如西班牙本土与拉美的电脑/鼠标用词、葡萄牙与巴西的人称和屏幕/桌面用词都可能不同。
- 同一语言的地区版本可以共享语义结构，但不能混用两地非常显眼的词汇和变位。若暂时只能提供一个版本，优先让相近地区玩家看到另一地区的同语言文本，而不是直接回退英文；有条件时再分别本地化。
- 游戏名 `Lucky Dog Rise` 在拉丁字母语言正文中通常直接保留，不套用中文书名号。是否使用斜体或当地引号服从 Steam 排版与该语言的自然习惯。
- 对不熟悉的语言，要主动核对当地 Steam 商店中的同类产品、平台固定栏目名称和实际术语；参考只用于确认自然用法，不能照抄其他游戏的宣传句。

## 文案验收清单

- 开头是否明确发生在电脑屏幕上，且不会被理解为现实中养猫、养鱼。
- 开头第一段与第二段在实际页面中是否形成平衡的居中排版，第二段是否短而有落点。
- “最大的幸运”是否明确属于小狗，配得感是否仍然成立。
- 小狗是否被写成安静陪伴而不索取的伙伴，且没有新增玩法承诺。
- Slogan 是否同时保留“生活磨损”和“小狗修补”两层情感，并具有当地语言的口号节奏。
- 开头与结尾是否形成“已有其他桌面伙伴，也可以再养这只小狗”的呼应，且没有替换、放弃已有桌宠或独占陪伴的暗示。
- 结尾是否同时保留“也给它一点位置”的加入感和略带委屈、试探、不愿添麻烦的请求语气，能够触动“也别把这只小狗落下”的心软与不忍，同时没有命令或强推销的感觉；不要把这种有意保留的轻微内疚感误判为需要消除的内容。
- 短描述是否覆盖核心玩法、字符与实际宽度是否合适、页面行数是否自然。
- 术语、代词、引号和语气是否属于目标地区，而不是另一地区变体或英语句法的影子。
- 正文中的“小狗”是否按上下文区分游戏或品牌身份、角色名称和亲昵代称，且没有将末尾关键词段落的独立选词任务混同为正文称呼翻译。
- 末尾关键词段落是否先完成目标语言的选词研究，再组织自然文案；确认采用的狗相关别称、热门昵称和搜索短语是否实际覆盖，而非只翻译中文段落或保留串词用的功能句。
- 完成一次正向朗读与一次反向释义：前者检查自然度，后者确认目标语言玩家实际接收到的关系与情感没有偏移。

## 末尾关键词与本地化

- 主人已在此前会话测试过在介绍下方自然融入变体关键词的做法。本目录沿用该方向，以增加被相关搜索发现的机会为目标。本区域的核心任务是研究并覆盖当地用户会使用的狗相关关键词，再把它们组织成自然文案。
- **核心判断问题：一个该语种的玩家，脑袋里想着狗时，可能会输入什么来搜索？** 从当地用户的语言习惯、狗名和文化记忆出发寻找词，再寻找与游戏的连接；不能只围绕游戏名称、“小狗”的译法或现有功能找近义表达，也不局限于明确带有“游戏”“桌宠”的搜索短语。
- 简体中文、英语、日语末尾已有额外介绍，用于融入当地的狗相关称呼、犬种、网络文化和桌面陪伴搜索表达。这些段落是有意保留的内容，不是重复文字或待清理的冗余。
- 中文可自然使用“狗子”“狗狗”“修狗”“旺财”等表达；英语、日语及其他语言应使用各自自然、相关的表达，不机械翻译中文昵称或梗。
- 主人提供的 `storepage_1315198_all.json` 中，捷克语末尾也已有同类介绍。核对其他语言时以实际导出为准，保留已有内容。

### 各语言的工作流：先选词，再写段落

1. **寻找狗的别称。** 调查目标语言用户实际使用的狗相关爱称、俗称、网络别称及常见写法，不能只从词典找几个“小狗”的近义词就结束研究。
2. **寻找热门狗狗的昵称与文化关联。** 调查当地热门狗狗、网红狗的昵称，以及与狗有关的梗和内容关联。目标是理解当地狗相关的网络文化，不能直接照搬中文热词或假定所有语言共享同一套梗。按外形描述的临时称呼应标为待核实，不得直接当成当地用户实际使用的梗名或搜索词。
3. **判断可能的搜索关键词。** 结合前两步，研究当地用户搜索狗、狗题材游戏或桌宠时可能使用的完整名称和短语。可参考当地平台的搜索联想、相关搜索、实际热门内容及相关推荐；主人提供的搜索或推荐截图也可作为选词线索。词典用于核实词义，不能替代搜索表达、文化关联与热度研究；不能凭空编造热词，也不能把未经核实的普通词都称为热词。
4. **核实名称并筛选可用关键词。** 区分发现的关联线索、待核实的候选词和最终采用的关键词。核实实际名称与当地用法，对关联性强或搜索价值高的候选词，主动尝试通过游戏形象、真实情况、玩笑、反差、相关作品比较或未来想象建立连接；不能仅因本游戏没有对应功能就直接排除。尝试后仍难自然衔接的词可以舍弃。“全部覆盖”仅指最终确认采用的词，不要求把整个关联链或所有候选词塞进文案。
5. **围绕选定关键词创作文案。** 先整理确认采用的词表，再把这些词全部自然融入描述。可选择真实玩法、产品特点、陪伴场景，也可明确说某功能“目前还没有”，或通过比喻、玩笑、比较和假设来串联。可以使用上述共用开头；后续句式、语序和具体讲述的功能都可因语言而不同，不要求逐句对齐中文，也不以翻译中文版段落代替当地选词与创作。
